Fusion Compiler Routing Rule 参数讲解

把这组参数理解成两件事：“怎么走” + “在哪些 metal layer 上走”。

NDR / Default Rule Min / Max Routing Layer soft / allow_pin_connection / hard soft cost

1. 先看整体逻辑

选择 net
→
选择 routing rule
→
限制可用层范围
→
决定越界是否允许
最重要的区分：
-rule / -default_rule / -no_rule 决定“采用什么布线规则”；
-min_routing_layer / -max_routing_layer 决定“希望在哪些层走”；
soft / allow_pin_connection / hard 决定“越界时到底有多严格”。

2. Routing Rule：怎么走

-rule rule

给 net 指定一个非默认布线规则 NDR。

常见用途：clock、特殊高速 net、需要加宽/加 spacing 的 net。

-default_rule

强制 net 使用默认 routing rule。

也就是不使用指定的 NDR。

-no_rule

移除当前 routing rule，让工具后续自行决定使用 default 或 nondefault rule。

注意：它不是“禁止 routing rule”，而是清掉当前显式规则。

-rule、-default_rule、-no_rule 三者互斥，不能同时指定。

3. Min / Max Routing Layer：在哪些层走

-min_routing_layer M4

设置该 net 的最低 routing layer 为 M4。

但到底能不能跑到 M1~M3，要看 -min_layer_mode。

-max_routing_layer M8

设置该 net 的最高 routing layer 为 M8。

但到底能不能跑到 M9 以上，要看 -max_layer_mode。

组合起来

min=M4 + max=M8

理想 routing 范围就是：

M4 ~ M8

4. 最关键：soft / allow_pin_connection / hard

soft：尽量别越界，但必要时可以

例如 -min_routing_layer M4 -min_layer_mode soft：

M1不推荐，但允许
M2不推荐，但允许
M3不推荐，但允许
M4正常使用
M5正常使用
M6+正常使用

本质：越界会增加 routing cost，而不是绝对禁止。

allow_pin_connection：主干不越界，pin 附近可以例外

例如 min layer = M4，standard cell pin 本身在低层：

M1仅 pin connection / 特殊 DRC
M2仅 pin connection / 特殊 DRC
M3仅 pin connection / 特殊 DRC
M4主干正常 routing
M5+主干正常 routing

直观理解：可以在 pin 附近“下去接一下”，接完尽快升回合法层。

hard：绝对不准越界

例如 -min_routing_layer M4 -min_layer_mode hard：

M1禁止
M2禁止
M3禁止
M4允许
M5+允许

特点：最严格，但也更容易因为 pin access / congestion / DRC 造成 routing 困难。

extract_only：只影响 extraction，不强制 routing

这些 min/max layer 约束主要用于 RC extraction 相关处理，在 global route optimization 时不作为实际 routing 强约束。

重点：它和 soft/hard 的思路不同，它不是“越界严不严”，而是“这个 layer constraint 主要拿来做 extraction”。

unknown：net 自己不显式设置

实际使用全局 app option：

route.common.net_min_layer_mode
route.common.net_max_layer_mode

也就是：net 没有自己的特殊规则 → 跟随全局设置。

5. soft cost：违反 soft 到底有多“贵”

值 含义 直观理解
low越界代价低工具比较容易选择越界
medium中等代价有必要时会越界
high越界代价高工具会强烈避免，但仍不是绝对禁止
unknown未显式指定由工具/默认设置决定
关键：soft + high 仍然不是 hard。
一个是“非常不想越界”，一个是“完全禁止越界”。

6. user-generated 标志

-min_layer_is_user true|false

true：最低层约束来自用户。

false：最低层约束由工具产生。

默认值：true

-max_layer_is_user true|false

true：最高层约束来自用户。

false：最高层约束由工具产生。

默认值：true

为什么要区分？

工具可以知道这个限制是人为要求，还是内部算法自动生成的约束。

7. -clear：全部先清空

-clear 会重置这些 net 上已有的：

  • routing rule
  • min / max routing layer
  • min / max layer mode
  • min / max soft cost

如果和其他参数一起写：

... -clear -min_routing_layer M4

执行顺序相当于：

先清空旧值 → 再设置 min routing layer = M4

8. 参数快速对照

-rule / -default_rule / -no_rule Routing Rule

决定 net 使用指定 NDR、默认规则，还是清除当前 rule 让工具自己决定。

-min_routing_layer / -max_routing_layer Layer Range

定义期望的最低层和最高层。例如 M4~M8。

-min_layer_mode / -max_layer_mode Strictness

决定超出 min/max layer 时，是允许、有限允许，还是完全禁止。

-min_layer_mode_soft_cost / -max_layer_mode_soft_cost Cost

只有 soft 模式下有意义，用于控制越界惩罚程度。

-clear Reset

清除当前 routing rule、layer constraint、mode 和 soft cost，再根据后续参数重新设置。

9. 最后用一句话记

soft

尽量别越界

allow_pin_connection

主干别越界，pin 附近可例外

hard

绝对不准越界

10. 示例

# 示例含义：
# 让目标 net 正常从 M4 开始走
# 但 pin connection 时允许临时使用更低层

set_routing_rule \
    -min_routing_layer M4 \
    -min_layer_mode allow_pin_connection \
    [get_nets MY_NET]

这类设置通常比直接 hard 更灵活，因为真实设计中 pin access 往往需要低层金属。
