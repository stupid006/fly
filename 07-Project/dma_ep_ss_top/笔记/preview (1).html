FC：set_clock_balance_points 中文翻译与讲解

根据 fc_shell man page（Version X-2025.06-SP1）整理
重点：用户手工指定用 -delay；-offset 是工具内部 CCD 使用

1. 这条命令到底是干什么的？

set_clock_balance_points 用来告诉 CTS：

  • 哪些 clock pin / port 要作为显式平衡点；
  • 哪些点要排除在 clock balancing 之外；
  • 某个 balance point 希望使用多少balance delay。
用户手工约束
-delay
告诉 CTS 我想怎么 balance
→
CTS
根据 balance point / delay
构造时钟树
place_opt + CCD
工具自动计算 useful skew
→
工具内部
-offset
用户不要手工设置

2. 语法

set_clock_balance_points
    [-rise]
    [-fall]
    [-early]
    [-late]
    [-consider_for_balancing true | false]
    [-offset offset_delay_applied_at_clock_sink_pins]
    [-delay delay_value]
    [-modes mode_list]
    [-corners corner_list]
    [-scenarios scenario_list]
    [-clock clock_list]
    -balance_points port_pin_list

3. 最重要的两个参数：-offset 和 -delay

-offset

man page 明确说明：这是工具在 place_opt 的 concurrent clock and data optimization（CCD）过程中，为 clock sink 自动生成的 offset delay。

原文结论： This option is used only by the tool.
也就是：这个选项只给工具自己用，用户不要手工设置。

-delay

这是用户自己指定 balance delay 的接口。

用户想手工告诉 CTS 某个点怎么 balance，应使用 -delay。
参数谁使用用途
-offset工具 / CCDplace_opt 中由 concurrent clock and data optimization 自动推导
-delay用户手工给 balance point 指定 balance delay

4. -consider_for_balancing

-consider_for_balancing true

这个点是一个 balance point，要参与显式 balancing。

如果只写 true 而没有写 -delay，工具默认 delay = 0。

-consider_for_balancing false

这个点变成 ignore point，即从 balancing 中排除。

不能这样写： 
set_clock_balance_points     -consider_for_balancing false     -delay 0.05     -balance_points ...
因为 false 表示“不参与 balancing”，而 -delay 又是在给它指定 balance delay，逻辑冲突，工具会报错。

5. rise / fall、early / late 默认行为

参数组如果都不写
-rise / -fall默认同时作用于 rise 和 fall
-early / -late默认同时作用于 early 和 late

所以一个最简单的：

set_clock_balance_points     -delay 0.05     -balance_points [get_pins U1/CK]

如果不再加别的限定，它会同时作用于 rise/fall 和 early/late。

6. MCMM：这个约束作用到哪些 scenario？

Balance delay 是按 scenario 管理的。

  • -scenarios：直接指定 scenario；
  • -modes：指定 mode，对应 mode 下的 scenario；
  • -corners：指定 corner；
  • -modes + -corners：取同时满足两者的 scenario。
如果这些都不写，默认只作用于 current scenario。
如果当前没有 current scenario，工具会报错。

7. -clock 与 -balance_points

-clock clock_list

指定这条 balance constraint 属于哪个 clock。对于 CTS，generated clock 被认为属于 master clock network，因此这里要求使用 non-generated clock。

-balance_points port_pin_list

指定真正要施加 balance point 的 port / pin。

set_clock_balance_points     -rise     -early     -delay 2.0     -clock clk1     -balance_points gck/CP

含义：

对 clock clk1，在 gck/CP 上建立一个 balance point，作用于 rise + early，其 balance delay 为 2.0。

8. Balance point 和 Ignore point

类型写法含义
Balance point-consider_for_balancing true 或使用 -delay这个点要参与 clock balancing
Ignore point-consider_for_balancing false这个点不参与 clock balancing

一个 pin / port 不能在同一个适用条件下既是 balance point，又是 exclude / ignore point。

9. Hierarchical pin 与 jump pin

Hierarchical pin

Balance point 可以设置在 hierarchical pin 上。

如果这个 hierarchical balance point 连到 dangling / black box，在 synthesize_clock_trees 时，工具会在它附近插入一个 guide buffer，再把约束移动到 guide buffer 的 input pin。

Jump pin

Jump pin 是出现在 generated clock source-latency network 中的 register clock pin。

如果 balance constraint 施加在 jump pin 上，clock network update / synthesis 时会被忽略。

10. 重复设置与 early / late 关系

  • 同一个 object + clock 上已有约束时，新约束可能覆盖或合并旧约束；发生覆盖会给 warning。
  • 如果只指定 early 或 late，工具会把对应另一边的值复制过去。
  • early value 不能大于 late value；如果发生这种情况，工具会 warning，并把 late 调整为 early。

11. 查看与删除

# 查看当前 balance points
report_clock_balance_points

# 删除 balance point constraints
remove_clock_balance_points ...

12. 三个官方示例怎么理解

示例 1：建立 balance point

set_clock_balance_points -rise -early -delay 2.0     -clock clk1 -balance_points gck/CP

解释：对 clk1，在 gck/CP 上建立 rise + early 的 balance point，delay 为 2.0。

示例 2：重复设置

再次对相同 object / clock / edge / analysis 设置 constraint 时，旧 constraint 会被覆盖，并产生 UIC-044 warning。

示例 3：建立 ignore point

set_clock_balance_points     -consider_for_balancing false     -clock clk1     -balance_points mux/A

解释：把 mux/A 从 clock balancing 中排除。

13. 你现在真正需要记住的

① 用户自己指定 balance delay：用 -delay
② -offset 是 CCD / 工具内部使用，不要手工写
③ -consider_for_balancing true = balance point
④ -consider_for_balancing false = ignore point

可以把整条命令理解成：

set_clock_balance_points
        │
        ├── -delay        → 用户告诉 CTS 这个点怎么 balance
        ├── -offset       → CCD / 工具内部的 offset
        ├── true          → 这个点参与 balancing
        └── false         → 这个点忽略 balancing

14. 和你前面学的 CCD 串起来

前面 PPT 里提到的 useful skew，重点要区分“工具内部产生”和“用户手工指定”：

place_opt + CCD
工具计算 useful skew
→
-offset
工具内部保存 / 传递
用户自己干预 CTS
希望指定 balance point delay
→
-delay
用户可用接口
这也是为什么培训 PPT 里看到 -offset 时容易误会：PPT 在解释 CCD 的内部机制，而 man page 明确区分了“工具内部接口”和“用户接口”。
