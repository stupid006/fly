00 · KNOWLEDGE MAP

先看全貌：所有名词原来是这样串起来的

PCIe 负责设备之间通信；Switch 负责转发 TLP；PHY 负责电信号收发；DMA 则是某个设备可以使用的自动搬运数据机制。

01 · BEGINNER

PCIe、CPU、RAM、SSD，究竟分别是什么？

CPU：执行者

执行程序、处理数据，控制系统运行。

RAM：临时工作台

保存正在使用的数据，通常断电内容丢失。

SSD：长期仓库

固态硬盘，使用闪存保存操作系统、照片、软件等，通常断电仍保留数据。

PCIe = Peripheral Component Interconnect Express，是一套让 CPU/SoC 与 SSD、网卡、GPU 等高速设备互相通信的标准。它不是存储器，也不是一种文件格式。

一个重要区别：NVMe 是很多 SSD 使用的存储命令/队列协议；PCIe 是下面的数据传输通道。部分 SSD 使用 SATA，而不是 PCIe。
02 · PHYSICAL CONNECTION

Port、Link、Lane 和 x1/x4/x16

Port 是设备的 PCIe 连接端口；两个 Port 之间建立的连接叫 Link；一条 Link 可包含多条 Lane。

每条 Lane 有一对 TX 差分线（TX+、TX−）和一对 RX 差分线（RX+、RX−），所以支持同时双向通信（全双工）。

“速率”和“带宽”不是一个词

代际每 Lane 传输速率单方向理论有效编码后带宽（近似）说明
PCIe 3.08 GT/s0.985 GB/s128b/130b，NRZ
PCIe 4.016 GT/s1.969 GB/s128b/130b，NRZ
PCIe 5.032 GT/s3.938 GB/s128b/130b，NRZ

GT/s 是每秒传输次数；上述 GB/s 仅扣除了线路编码开销，未扣 TLP Header、其他协议开销。PCIe 6.0 等更新代际使用不同技术（如 PAM4/FLIT），不能直接沿用同一简化公式。

04 · SWITCH FABRIC

Switch 内部为什么有 FIFO、Arbiter、Crossbar？

FIFO / Buffer

先存着。 一个输出口忙时，数据不能丢，需要等待。

Arbiter（仲裁）

谁先走。 多个输入争抢同一个输出时，决定授权顺序。

Crossbar（交叉开关）

从哪到哪。 将已获授权的输入与目标输出连通。

交互实验 · Switch 把 TLP 转发给谁？点击目标设备

↓
Switch Fabric检查地址，转发到 Port 2
↓
正在把一个 Memory Read Request 转发到 SSD 2（Port 2）。返回的 Completion 将向请求者方向路由。

多个输入争抢一个输出

例如 SSD 1 和 SSD 2 同时想往 CPU 上行口发数据。二者不能在同一个受限的输出资源上无限制同时发送：缓存等待、仲裁选路、交换结构完成传输。

三词口诀：FIFO 负责“等”，Arbiter 负责“选”，Crossbar 负责“送”。但实际 Switch 内部还涉及排序规则、Credit 流控、输入/输出缓冲与链路协议，并非简单的单级 MUX。

Upstream 与 Downstream 指拓扑方向，并非单向数据线。每条 PCIe Link 都能双向通信，Switch 的每个外部 Port 都需独立完成 PHY 与链路处理。

Switch 不创造额外上行带宽。例如 3 个 x4 下行设备共享一个 x4 上行口，大量同时向 CPU 发送时，上行 x4 仍可能成为瓶颈。

05 · PROTOCOL

PCIe 的三层协议，与最重要的 TLP

Transaction Layer（事务层）决定要读还是写，生成和解释 TLP
↓↑
Data Link Layer（数据链路层）链路级可靠传输：LCRC、ACK/NAK、重传、流控
↓↑
Physical Layer（物理层）链路训练、数据编码/恢复、高速 SerDes 电信号

TLP 是什么？

TLP = Transaction Layer Packet（事务层数据包）。它是 PCIe 中传递读请求、写请求、响应以及其他事务信息的主要包格式。不是只发裸的 0101，而是有说明信息的“快递包”。

TLP 的简化结构
Header 包头类型 / 地址 / 长度 / 标识等
Payload 数据部分 TLP 有，部分没有
可选 DigestECRC 等
包头和数据的区别：Header 像快递单，说明要往哪儿送、什么事务；Payload 像快递盒里的实际数据。

ECRC 与 LCRC 不一样

LCRC · Link CRC

数据链路层使用，重点检查一段 PCIe Link 的传输，关联链路级 ACK/NAK 与重传。

ECRC · End-to-End CRC

可选的 TLP 端到端完整性检测（TLP Digest），与某一段链路的 LCRC 作用范围不同。

你的小模块有“ECRC 校验 / 剥离”功能，但不能直接推断它是透明 Switch 必须做的事情；需要判断它是否终止/重新生成对应 TLP 或处在某个本地处理路径。

你截图里的“Completion 缓冲区”是什么？

它用于暂存 Completion 响应包或相关数据，不等于“整个 DMA 任务已经完成”的状态寄存器。

两个“完成”要分开：
① PCIe Completion：对某个 Non-Posted 请求的协议响应。
② DMA Task Completion：一个搬运任务真正结束，可更新状态或触发中断。二者不一样。

还有 MPS 与 Ordering

MPS（Max Payload Size）规定一个 TLP 的最大 Payload，生成端需要按限制打包。Ordering 则规定 PCIe 不同 TLP 的先后顺序限制；并非所有事务都能任意重排，也并非所有事务必须严格 FIFO。

特别注意：MPS 分拆更像数据产生端的打包逻辑。一个普通透明 Switch 通常负责转发过境 TLP，不能默认会把每个收到的包重新切碎。

07 · PHY & PIPE

PHY 与 PIPE：一个是硬件，一个是接口

PHY（Physical Layer 硬件实现）

真正负责高速电信号收发，包括 SerDes、时钟恢复和模拟前端等硬件。

PIPE（PHY Interface for PCI Express）

定义 MAC/Controller 一侧与 PHY 之间如何交换数据、状态、时钟和控制信息，是标准接口规范。

最典型的功能关系
SoC / DMA / AXI 等逻辑
↓↑
PCIe Controller / MACTLP、链路控制、协议处理
↓↑
PIPE Interface片内数据、控制、时钟和状态交接
↓↑
PCIe PHY / SerDes高速串行收发，含混合信号电路
↓↑
TX± / RX± → PCB → 对端

为什么要 PIPE？可以让兼容的 Controller 和 PHY 更容易集成、验证和复用。实际版本可能采用不同宽度、时钟组织和 PHY/MAC 功能边界，不能把某一组 PIPE 信号名当成所有代际的唯一实现。

对 PD 最重要的区别：Controller 侧主要是标准单元数字逻辑；高速 PHY 可能作为 Hard Macro / Analog-Mixed-Signal IP 集成。两者之间的 PIPE 数字接口仍需做时序、CDC、物理连线检查。
08 · HIGH-SPEED PHY

SerDes、PLL、CDR 分别干什么？

1. SerDes：并行 ⇄ 串行

Serializer：把一拍内的多 bit 并行数据依次串行发送。Deserializer：把接收到的串行 bit 重新组成并行数据。这样外部能用少量高速差分通道，而芯片内部使用较宽的数据总线。

交互实验 · 8 bit 串并转换10110010

2. PLL：产生所需的高速时钟

PHY 可以使用参考时钟（常见 PCIe 架构有 100 MHz Refclk），通过 PLL 等电路产生内部所需的高速时钟。PLL 不等于 CTS：PLL 是时钟产生/同步电路；CTS 是 PD 里将时钟分配给大量寄存器的物理树结构。

3. CDR：恢复正确的采样时序

接收端即使知道标称传输速率，也不一定知道数据到达的准确相位。CDR（Clock and Data Recovery）通过接收信号的跳变信息调整采样时钟，尽量在 bit 稳定的位置采样。

交互实验 · 采样位置为什么重要？50%
此时采样点在 bit 中心附近，通常更安全。

这是教学波形，不是晶体管仿真。真实安全采样区不是固定的 30%—70%，还取决于抖动、噪声、建立/保持时间和接收器实现。

09 · LINK TRAINING

LTSSM、TS1、TS2：为什么连接好还不能直接通信？

LTSSM = Link Training and Status State Machine。PCIe 上电后，需要检测对端、交换训练序列、配置 Lane、建立数据接收同步，才能进入正常传输状态。

TS1 / TS2 是什么？

TS = Training Sequence（训练序列）。TS1、TS2 属于物理层有序集（Ordered Set），用于链路训练、同步与配置。它们不是普通 Memory Read、Memory Write，也不是 CPU 的文件数据。

阶段大致做什么训练信息
Detect检测对端接收器主要电气检测，并非正常发 TLP
Polling建立接收同步，交换训练序列常见 TS1、TS2
Configuration协商/配置 Link、Lane 编号和宽度TS1、TS2
L0正常链路活动，配合完成必要链路初始化可传输正常事务
Recovery重新训练、速率切换、信号调整等视代际和子状态而定

早期 Gen1/Gen2 经典 TS 有序集含 16 个 Symbol，并有 Link Number、Lane Number、N_FTS、Data Rate、Training Control、TS 标识等字段。不同 PCIe 代际/状态的训练格式不完全相同，不能把 TS1 理解成“永远提问”、TS2 理解成“永远回答”。

排查 Link Up 失败时：看 LTSSM 卡在哪个状态、协商到的 Lane 宽度/速度、训练序列接收情况、PHY/板级信号完整性等。数字逻辑 STA 通过并不足以证明链路一定训练成功。
10 · DMA TRANSACTION

DMA、Descriptor、Completion、MSI 一口气理清

Descriptor 是“任务单”，DMA Engine 是“搬运工”，Completion 是“某个 PCIe 请求的回复”，MSI 是“通知 CPU 的中断消息”。

Descriptor 描述符

保存源地址、目的地址、长度、控制等信息。不是被搬运的大量数据本身。

eDMA 引擎

根据任务自动执行内存/设备之间的数据搬运，包含读/写 Engine、控制与状态管理等。

Completion 响应

例如 DMA 发出 Memory Read，主机可能用多个 Completion with Data 把结果返回。

LL（链表） 让 DMA 不必每次都等待软件逐个启动传输，可以按描述符序列执行多个任务。MSI 在任务满足中断条件时通知主机，但不等于每收到一个 PCIe Completion 就必定发送一次 MSI。

12 · 3 TLP SRAM

第一组：Posted、Non-Posted、Completion 三颗 SRAM

为什么 CPL2MWR 和 Completion Buffer 不是一回事？

Completion Buffer

主要存返回的数据内容/包缓冲。

CPL2MWR LUT

主要存返回数据对应的地址/目标/处理上下文。

可以理解为“货物仓库”与“货物对应的派送地址记录”。并不代表二者没有关联，而是存储内容不同。摆放要看谁直接访问 SRAM，而不只看两者名字都出现 Completion。

这一节的组别是根据功能做的 Floorplan 假设：同尺寸、同 RTL 层级也不意味着一定存在 SRAM-to-SRAM 直连。

ECC、MBIST、BISR 怎么理解？

ECC

运行时检测与纠正存储数据错误。SECDED 常表示单比特可纠、双比特可检。

MBIST

Memory Built-In Self-Test，存储器内建自测试，用于发现 SRAM 硬件缺陷。

BISR

Built-In Self-Repair，结合冗余资源对支持的缺陷进行修复；不是 ECC 的同义词。

你提供的截图提到 cfg_ras_ecc_correct_en、IRQ_ECC_RD_DATA_BUFFER_1bit_ERR、ecc_info_unit，说明 Buffer 有运行时纠错控制、错误上报与信息收集。另外还提到 MBIST Collar + BISR 修复；对 Floorplan 而言，这些外围控制逻辑也可能带来共享总线、测试控制信号和区域内连线。

190 条时序违例：你提供的分析曾提到 ren_sel_dl_reg 相关路径和约 190 条 Reg-to-Reg 违例。它是待验证线索，不能凭截图断定所有违例由 66 颗 Macro 的摆放造成；要看真实路径的 Cell Delay / Net Delay 比例以及路径是否经过 Macro。

每次调整 Macro 的结果要看什么？

一个很实用的判断：如果 u0/u1 是拼位宽，两者不一定大量直接互连；它们真正共同访问的可能是 ECC / Data MUX / Bank Decoder。相比强行缩小 Pair 间距，确定读写数据的源与终点更重要。
16 · FC / TCL

在 Fusion Compiler 里实际怎么检查？

这里优先给你短而能复制的探查命令。不同 FC 版本对象属性可能存在差异；遇到属性不存在时先用 list_attributes、get_attribute、man 检查，不要直接依赖某个版本中的名字。

① 获取 Hard Macro 的名字、库参考名和物理 bbox
set macros [get_cells -hierarchical -filter "is_hard_macro == true"]
puts "Macro count: [sizeof_collection $macros]"
foreach_in_collection m $macros {
    puts "[get_object_name $m] | [get_attribute $m ref_name] | [get_attribute $m bbox]"
}
② 只过滤 RD_DATA_BUFFER 这一层下的 Macro
set all_macros [get_cells -hierarchical -filter "is_hard_macro == true"]
set rd_macros [filter_collection $all_macros \
    "full_name =~ *RD_DATA_BUFFER_ECC_wrapper*"]
puts "RD Buffer Macro count: [sizeof_collection $rd_macros]"
③ 检查一颗 Macro 的真实 Pin、Net（先选你实际存在的 Instance）
# 把这一行换成 FC 中实际存在的全路径
set m [get_cells {YOUR_FULL_MACRO_INSTANCE_NAME}]
set pins [get_pins -of_objects $m]
puts "Pin count: [sizeof_collection $pins]"
foreach_in_collection p $pins {
    set nets [get_nets -quiet -of_objects $p]
    if {[sizeof_collection $nets] == 0} { continue }
    puts "[get_object_name $p] => [get_object_name $nets]"
}
④ 从 66 颗里识别 Gen_sram 编号和 u0/u1
foreach_in_collection m $rd_macros {
    set name [get_object_name $m]
    # 兼容路径中的 Gen_sram_7/.../u0 或其他中间层级：
    if {[regexp {Gen_sram_([0-9]+)} $name -> idx]} {
        puts "Group=$idx  Instance=$name"
    }
}
# 真正的 u0/u1 字符格式要看 get_object_name 实际打印结果。
这些命令能做到什么、不能做到什么：它们可列出 Macro、Pin、连接的 Net、几何位置；但简单 get_nets -of_objects 只能看到直接连接，不会自动跨越 Buffer/MUX/逻辑门追溯整个功能数据流。分析“谁主要访问 SRAM”时还需进一步按驱动/负载 Instance 归类，或结合时序与 GUI Connectivity。

8 个最容易误解的地方

  1. Completion 是一种 TLP；不是 TLP 之外的独立协议。
  2. Completion 到达 ≠ 整个 DMA 任务必定完成。
  3. Descriptor 存任务信息，Data Buffer 才通常存大批实际数据。
  4. Switch 负责路由 TLP，Retimer 负责重新定时物理信号。
  5. PHY 是实际硬件，PIPE 是接口规范。
  6. 同一个 RTL Hierarchy，不等于 Macro 物理上必须紧贴。
  7. 同一组 u0/u1 拼位宽，不代表两颗 Macro 之间必须直连大量数据线。
  8. 宏规格里的 128×288 是深度 × bit 位宽，不是物理长 × 宽（μm）。
