1. set_clock_latency 是干什么的？

Specifies the latency of a clock network.
翻译：指定时钟网络的 latency（延迟）。

你可以把它理解成：告诉 STA，“这个 clock 从某个起点走到某个位置，需要多少时间”。

Total Clock Latency = Source Latency + Network Latency
真实时钟源
PLL / 外部时钟
→
Clock Definition Point
create_clock 定义的位置
↑ 这一段叫 Source Latency
Clock Definition Point
→
Register / SRAM Clock Pin
↑ 这一段叫 Network Latency

2. Source Latency 和 Network Latency

Source Latency

set_clock_latency 0.5 -source [get_clocks CLK]

表示从真正的 clock waveform origin 到设计里的 clock definition point 之间有 0.5 的延迟。

常见用途：
  • 芯片外部 PLL / clock board delay
  • clock generation circuit 不在当前 block 内
  • generated clock 的 master → generated clock definition point 建模

Network Latency

如果不写 -source，默认就是 network latency。

set_clock_latency 1.0 [get_clocks CLK]

表示从 clock definition point 到 register clock pin 的 clock tree 延迟，先假设为 1.0。

最常见理解： pre-CTS 阶段 clock tree 还没真正建好，就用 network latency 先“估一个未来 clock tree 延迟”。

3. Pre-CTS 与 Post-CTS

Pre-CTS

时钟树还没有真实 buffer / route，因此一般是 ideal clock。

set_clock_latency 1.0 [get_clocks CLK]
CLK
→
假设 network latency = 1.0

Post-CTS

CTS 后有真实 clock tree，就通常切到 propagated clock：

set_propagated_clock [get_clocks CLK]
CLK
→
BUF + INV + Route RC + 实际 Clock Tree
关键区别：
Pre-CTS：主要依赖 ideal clock + set_clock_latency。
Post-CTS：主要依赖 propagated clock 的真实延迟。

4. 主要参数逐个解释

-rise / -fall

set_clock_latency 1.2 -rise [get_clocks CLK1]
set_clock_latency 0.9 -fall [get_clocks CLK1]

-early / -late

set_clock_latency 0.8 -source -early [get_clocks CLK1]
set_clock_latency 0.9 -source -late  [get_clocks CLK1]
early = clock 较早到时的分析值；late = clock 较晚到时的分析值。

-min / -max

指定 minimum / maximum operating condition 的 latency。OCV 下主要使用 min-early 和 max-late。

-clock

set_clock_latency 0.1     -clock [get_clocks CLK1]     [get_pins U1/CK]
工具不会在 UI 层检查 CLK1 是否真的经过 U1/CK；如果根本不经过，这条约束可能没有效果，但也不报错。

-dynamic

set_clock_latency 3 -source -early     -dynamic 0.5 [get_clocks CLK1]

表示 source latency 中的动态部分，只能与 -source 一起使用，主要用于 CRP/CRPR 与 zero-cycle path。

5. -offset 与 CCD 的关系

man page：-offset 用于 clock network sink 或 ICG clock pin 上的 offset latency。
place_opt + CCD
计算 useful skew
→
set_clock_latency -offset
记录某个 sink 的 latency adjustment

例如 CCD 希望某个 FF clock 晚 50ps：

set_clock_latency 0.05 -offset [get_pins FF2/CK]
这里不是普通 network latency，而是针对某个 clock sink / ICG pin 的局部 offset。
不要把它和普通用户 network latency 混在一起。 你前面的 Synopsys CCD 培训资料把它作为 useful-skew 优化中的工具内部机制。

6. 给 pin / port 设置 network latency 会怎样？

如果 set_clock_latency 施加在 pin 或 port 上，会影响这个 pin/port transitive fanout 中的所有 register clock pins。
U1/CKIN
→
FF1/CK、FF2/CK、FF3/CK ...
set_clock_latency 0.5 [get_pins U1/CKIN]
更关键：直接给 pin/port 设置 network latency，会让受影响的 registers 变成 ideal clock。
命令含义
set_propagated_clock使用真实 clock tree 延迟
set_clock_latency network使用 ideal network latency

7. Generated Clock 的 source latency

Master Clock
→
Generated Clock Definition Point

如果 master clock 已经 propagated，而且 generated clock 没有人为 source latency，工具会自动计算 generated clock 的 source latency。

如果 master clock 还是 ideal，master clock 有 source latency，但 generated clock 没有用户指定 source latency，那么 generated clock 默认 source latency = 0。

8. MCMM：Latency 是 per-scenario 管理的

可以使用 -modes、-corners、-scenarios。

set_clock_latency 1     [get_clocks CLK]     -corners [get_corners corner1]
如果这些都不写，默认只作用于 current scenario。

9. 官方示例翻译

示例 1：分别设置 rise / fall network latency 
set_clock_latency 1.2 -rise [get_clocks CLK1]
set_clock_latency 0.9 -fall [get_clocks CLK1]

CLK1 的 rise latency = 1.2，fall latency = 0.9。

示例 2：设置 early / late source latency 
set_clock_latency 0.8 -source -early [get_clocks CLK1]
set_clock_latency 0.9 -source -late  [get_clocks CLK1]

CLK1 的 early source latency = 0.8，late source latency = 0.9。

示例 3：source latency + dynamic component 
set_clock_latency 3 -source -early -dynamic 0.5 [get_clocks CLK1]
set_clock_latency 5 -source -late  -dynamic 0.5 [get_clocks CLK1]

early / late source latency 分别是 3 和 5，其中 dynamic component 都是 0.5。

示例 4：给 clock source port 指定相对 clock 
set_clock_latency 3 -source -early -dynamic 0.5     -clock [get_clocks CLK1] [get_ports CLK]

给 source port CLK 设置 source latency，并明确它是相对于 CLK1。

示例 5：不同 corner 使用不同 latency 
set_clock_latency 4 -source [get_clocks CLK1]     -corners [get_corners {corner1}]

set_clock_latency 5 -source [get_clocks CLK1]     -corners [get_corners {corner2 corner3}]

set_clock_latency 1 [get_clocks CLK1]

set_clock_latency 2 [get_clocks CLK1]     -corners [get_corners {corner2}]

set_clock_latency 3 [get_clocks CLK1]     -corners [get_corners {corner3}]

同一个 clock 在不同 corner 下可以有不同 source latency 和 network latency。

11. 和 set_clock_balance_points 的区别

命令主要作用核心意义
set_clock_latencySTA / timing model描述 clock arrival / propagation 应该假设多少 latency
set_clock_balance_pointsCTS balancing描述这个 clock point 应该怎样参与 balancing
place_opt CCD
算 useful skew
→
set_clock_latency -offset
pre-CTS timing 记录 sink adjustment
Useful-skew intent
→
set_clock_balance_points
CTS 中实现 balancing target
一句话记忆：
set_clock_latency 更像描述“clock 到了多少”；
set_clock_balance_points 更像告诉 CTS“这个 clock point 应该怎么 balance”。

12. 最后只记这 6 句话

  1. Source latency：真正时钟源 → clock definition point。
  2. Network latency：clock definition point → register clock pin。
  3. Pre-CTS 常用 ideal clock + set_clock_latency 做估算。
  4. Post-CTS 通常切到 set_propagated_clock，使用真实 clock tree latency。
  5. -offset 是 clock sink / ICG pin 的局部 offset，CCD 会用它表达 useful-skew adjustment。
  6. 给 pin/port 直接设 network latency 时要小心，它会让受影响 register 变成 ideal。
