Congestion-Aware Initial CTS

build_clock
├─ CTS  = Initial Clock Tree Synthesis
└─ CTO  = Clock Tree Optimization
默认下
CTS 阶段  → Virtual Routing，VR
CTO 阶段  → Global Routing，GR

> **`build_clock` 里面前面的 initial CTS 默认不 congestion-aware，因为它使用 VR。**

后面的 CTO 默认已经会用 GR
VR 不考虑高 congestion 区域和 routing blockage

```
cts.compile.enable_global_route true
```

让 initial CTS 这一段也从 VR 改成 GR

默认 build_clock 前半段 CTS 用 VR 快速建树，不看拥塞；后半段 CTO 用 GR 修正。打开 `cts.compile.enable_global_route` 后，CTS 一开始建树时就考虑 congestion/blockage，因此更接近最终 routing。

Redundant Via Insertion（冗余 Via 插入）
把原本只有一个 cut 的 via，尽量换成 **多 cut via** 或者更可靠的 via 结构，主要为了 **DFM 和可靠性**

可靠性更高，但占空间更多、routing 更难收敛,SI可能会下降

```
route.common.post_detail_route_redundant_via_insertion = medium

route.common.concurrent_redundant_via_mode = reserve_space

route.common.concurrent_redundant_via_mode = insert_at_high_cost
```


![[Pasted image 20260921104251.png]]![[Pasted image 20260921104317.png]]

**先进工艺（<20nm）里，不建议每次 Detail Route 都顺手做 RVI，而是“先给它留位置，等 routing 基本干净后，再单独跑一次 `add_redundant_vias`”。** 这样主要是为了 **更容易 DRC 收敛、减少总 runtime**。


```
set_app_options -list {
    route.common.post_detail_route_redundant_via_insertion off
    route.common.concurrent_redundant_via_mode reserve_space
    route.common.eco_route_concurrent_redundant_via_mode reserve_space
}
```

![[Pasted image 20260921105333.png]]

![[Pasted image 20260921110246.png]]

在 route_auto（带 add_redundant_vias）之后单独执行 RVI，而不是在布线过程中执行，这纯粹是一种节省运行时间的技巧——并不会带来更好的转换率：如果设计中有很多 DRC（与 RVI 无关），可能需要多次运行 route_auto。上述方法允许先完成所有为了修复这些 DRC 所需的布线操作，而不必增加运行 RVI 的额外时间。之后，再执行一次单独的 RVI（如果需要，在 route_opt 之后可再执行一次）。

为了配合 redundant via，router 会尽量把线走得更直、减少 via；必要时宁可在同一层走一小段 non-preferred-direction jog，也可能比“换层 + 多个 via”更划算，也可以在 `route_auto` 后单独跑 `optimize_routes`
![[Pasted image 20260921112803.png]]
non-preferred-direction jog肯定不是越多越好，怎么控制-->
```
set_app_options  -name route.common.extra_nonpreferred_direction_wire_cost_multiplier_by_layer_name -value {{layer multiplier}...
```
Multipier value必须在0到20之间，默认值是0。指定较大的值可能会完全阻止非优选方向的路由。如果需要在非优选方向上进行路由，可以使用较小的值。像0.25或0.5这样的小倍增值是有效的，有时足以达到想要的效果。在评估倍增值时，你还应该检查所有层和方向的总连线长度，因为倍增值过大可能会限制布线器自由度，从而增加连线长度

# 922
Via Ladder 的目的不是“为了好看”，而是通过降低 pin 到主干走线之间的 via/局部连接电阻，改善 net delay、transition，最终把 timing slack 往好的方向推
Via Ladder 越有效，**pin 到主走线的局部连接电阻越小**，因此 **net delay ↓、transition ↓、slack 改善**
