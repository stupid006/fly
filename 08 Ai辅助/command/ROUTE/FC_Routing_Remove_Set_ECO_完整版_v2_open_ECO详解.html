一句话先抓住 remove_routes

它不是“删 net”它删除的是 net 上的 routing shapes：wire / via / fill / ring / stripe 等。
必须指定 shape use至少要带一个如 -detail_route、-user_route 等选项。
可按 net / net type 筛选-nets 控具体 net，-net_types 控 signal/clock/power/ground 等。
ECO 典型用途先删旧 detail route，再重新施加 routing rule，然后 route_eco 重走。
最容易误解：remove_routes 不会删除逻辑连接，也不是 disconnect_net。它只是把物理走线 shape 从数据库里删掉，net 本身仍然存在。

核心语法

remove_routes
  [-nets nets]
  [-net_types list_of_net_types]
  [-detail_route]
  [-global_route]
  [-user_route]
  [-shield_route]
  [-ring]
  [-stripe]
  [-lib_cell_pin_connect]
  [-macro_pin_connect]
  [-follow_pin]
  [-core_wire]
  [-zero_skew]
  [-area_fill]
  [-opc]
  [-rdl]
  [-keep_pg_pins_at_boundary]
  [-keep_frozen_nets]
必须注意：man page 明确说这个命令至少要指定一个 shape use option。也就是说，单写 remove_routes -nets $n 是不完整的思路。

先理解：它到底在删什么？

逻辑 Net
driver / load / connectivity 仍然保留
Routing shapes
wire、via、detail route、user route、shield、ring、stripe... 可被删除
删除后状态
逻辑还连着，但物理上可能变成 open，需要后续重新 route

筛选对象：-nets 与 -net_types

-nets nets指定具体 net
MAN 原意
指定要删除 net shapes 的 nets。
怎么理解
最适合 ECO：你已经知道哪几条 net 要重布，就只针对这些 net 删除指定 shape use。
remove_routes -nets [get_nets n1] -detail_route
-net_types list按类型过滤

可选：analog_ground、analog_power、analog_signal、clock、power、ground、signal、tie_high、tie_low。

如果同时用了 -nets 和 -net_types，两者是交集。某个 net 即使在 -nets 里，但它不属于指定 net type，也会被忽略。
# 只删除 n1/n2 中属于 signal 类型的 detail route
remove_routes \
    -nets [get_nets {n1 n2}] \
    -net_types signal \
    -detail_route

Shape Use 选项：每一个到底删什么

选项删除对象常见理解
-detail_routeshape_use = detail_route最终 detail routing 的 wire/via，ECO 最常见
-global_routeglobal route shapes删除 global routing 结果
-user_routeuser route shapes人为/用户生成的 routing
-shield_routeshield routeshielding 相关走线
-ringring shapes常见于 PG ring
-stripestripe shapes常见于 PG stripe
-lib_cell_pin_connectlib cell pin connect库 cell pin 附近连接 shape
-macro_pin_connectmacro pin connectmacro pin 接出部分
-follow_pinfollow pin shapesstandard cell rail / PG 常见
-core_wirecore wirePG core wire 类 shape
-zero_skewzero skew shapes特殊 routing use
-area_fillarea fillrouting fill
-opcOPC shapes特殊用途 shape
-rdlRDL shapesredistribution layer routing

-keep_frozen_nets：很重要

MAN 原意
保留 frozen nets 的 shapes。frozen net 指 physical_status = locked 的 net。
实际意义
如果设计里有你明确 lock 住、不希望 ECO 过程中破坏的 routing，带这个选项可以避免它们被 remove_routes 删除。
remove_routes \
    -net_types signal \
    -detail_route \
    -keep_frozen_nets
这和 route_eco 里 frozen net “router 不修改”的概念是对应的：一个负责删线时保护，一个负责重布时保护。

-keep_pg_pins_at_boundary 是干嘛的？

针对 PG routing。默认情况下，如果 cell boundary 上的 PG pin 被 PG net shape 覆盖，删除 PG route 时这些 pin 也会一起被移除。

加上 -keep_pg_pins_at_boundary 后，这些边界 PG pin 会被保留。
而且 man page 特别强调：一旦保留下来，后续再次执行 remove_routes 时，因为这些 pin 已经不再被 PG route 覆盖，所以不会再被后续 remove 删除。

最危险的情况：只写 shape use，不指定 net

remove_routes -detail_route
这不是“删当前选中的 net”。
man page 的行为是：删除所有可由 -net_types 表示的 net type 上的 detail-route shapes，同时还会删除 no-net shapes。

所以在 ECO 场景里，除非你真的想大范围清 route，否则建议明确带 -nets 或 -net_types。

典型使用模板

模板 A：只删除某条 ECO net 的 detail route 
set eco_nets [get_nets {n1 n2}]
remove_routes -nets $eco_nets -detail_route

这是最像你实际 ECO 的写法。

模板 B：删除某条 net 的 detail + global route 
remove_routes \
    -nets [get_nets n1] \
    -detail_route \
    -global_route

相当于把该 net 的 routing 规划和 detail implementation 都清掉，后续重新 route 的变化更大。

模板 C：清 signal detail route，但保护 frozen nets 
remove_routes \
    -net_types signal \
    -detail_route \
    -keep_frozen_nets

一句话先抓住 remove_shapes

操作对象直接删除你明确指定的 shape objects。
不是按 net 类型删它不关心 detail_route / signal / clock 这些高层语义，只认 shape collection。
更像“手术刀”适合只删一小段 wire/via/局部 geometry。
返回值返回实际删除的 shape 数量。
核心区别：remove_shapes 是 object-level 删除；remove_routes 是 routing-semantics-level 删除。

核心语法

remove_shapes
  [-force]
  [-verbose]
  shape_list

参数解释

shape_list真正的核心
MAN 原意
指定要删除的 shapes，可以直接传入 get_shapes 得到的 collection。
怎么理解
你先自己把具体 shape object 选出来，再交给 remove_shapes。工具不会像 remove_routes 那样再帮你根据 shape_use 或 net type 做二次语义筛选。
set ss [get_shapes -of_objects [get_nets n1]]
remove_shapes $ss
-force高风险
MAN 原意
忽略 affected objects 的 locked status。若不带此选项且受影响对象被 locked，命令会报 Tcl error。
怎么理解
默认行为是“看到 locked 就停”。加上 -force 后，工具会无视 locked 状态继续删，所以这是典型的危险开关。
不要把 -force 当常规选项。除非你明确知道 collection 中有哪些 locked 对象，以及为什么必须删除。
-verbose调试/确认

逐个显示被删掉的 shape，适合你想确认到底删了哪些对象。

remove_shapes -verbose $ss

它删掉 shape 后，数据库发生什么？

man page 说明：被删除的 shape 会与其关联的 net、port、terminal、layer、edit group 等解除关联。

普通 routing shape
shape 删除；对应物理 geometry 消失
Terminal shape
shape 删除，同时 associated terminal 也删除
Port shape
shape / associated terminal 删除，但 port 本身仍保留
因此：如果你的 get_shapes collection 取得太宽，不小心包含 terminal/port 相关 shape，后果不只是“少了一小段线”。

一个最直观的例子

# net_A 上有很多 shape
set all_shapes [get_shapes -of_objects [get_nets net_A]]

# 但我只拿其中某一小段
set target_shape [get_shapes -filter "name == PATH_18_1906"]

# 只删这一段
remove_shapes -verbose $target_shape
删除前
shape_1 ─ shape_2 ─ shape_3 ─ shape_4
remove_shapes
只删除 shape_2
删除后
shape_1 ─ [OPEN] ─ shape_3 ─ shape_4

什么时候它比 remove_routes 更合适？

场景更适合的命令原因
整条 net 的 detail route 准备重走remove_routes按 net + shape_use 语义删除，更安全、更直接
只想删 M6 上某一小段 wireremove_shapes可以精确到具体 shape object
只想删某几个 viaremove_shapesobject-level 精准控制
想清某条 net 的所有 detail_routeremove_routes无需自己枚举所有 shapes

remove_routes vs remove_shapes

remove_routes按 net / net type / shape_use 批量拆线。
remove_shapes按具体 shape object 精确删除。
前者像“拆一类线”更适合 reroute 某条 net。
后者像“手术刀”更适合局部 geometry 修补。

同一条 net 上的例子

net_A

一句话先抓住 set_routing_rule

它在干什么给指定 net 绑定 routing rule / min layer / max layer / layer mode。
NDR可通过 -rule 指定用 create_routing_rule 建好的 nondefault rule。
Layer 约束可以限制某 net 最低/最高在哪些金属层范围走。
关键区别soft 是“尽量别越界”，hard 才是“绝对不许越界”。

核心语法

set_routing_rule
  [-rule rule | -default_rule | -no_rule]
  [-min_routing_layer layer]
  [-max_routing_layer layer]
  [-min_layer_mode mode]
  [-max_layer_mode mode]
  [-min_layer_mode_soft_cost cost]
  [-max_layer_mode_soft_cost cost]
  [-min_layer_is_user true|false]
  [-max_layer_is_user true|false]
  [-clear]
  [net_list]

三个 routing rule 状态

选项实际含义直观理解
-rule WideMetal明确给 net 绑定一个 NDR“就用这个规则”
-default_rule明确指定默认 routing rule“走默认线宽/间距”
-no_rule移除当前显式 rule，让工具自动决定“我不指定，交给工具”
-rule、-default_rule、-no_rule 三个互斥。

Min / Max Routing Layer + Mode

Mode是否允许越界解释
unknown取全局 optionmin 用 route.common.net_min_layer_mode，max 类似
extract_onlyrouting 阶段不作为实际约束主要给 extraction 使用
soft允许越界会增加 cost
allow_pin_connection有限允许pin connection 或极端拥塞修 DRC 时允许
hard不允许严格禁止越界
最好记：soft = “能破例，但有代价”；hard = “不能破例”。

soft cost

值意思
low越界惩罚较低
medium中等惩罚
high强烈不希望越界
unknown不在 net 上显式指定 cost

-clear：会清一整套 net-based routing constraint

set_routing_rule -clear [get_nets n1]
-clear 不只是清 NDR，还会清 min/max routing layer、mode、soft cost 等。

典型例子

# NDR
set_routing_rule -rule WideMetal [get_nets B_CLK]

# 主体希望在 M4~M8，pin connection 可破例
set_routing_rule \
    -min_routing_layer M4 \
    -max_routing_layer M8 \
    -min_layer_mode allow_pin_connection \
    -max_layer_mode allow_pin_connection \
    [get_nets critical_net]

一句话先抓住 route_eco

使用时机signal routing 已经完成之后。
第一件事连接 open net。
第二件事修 ECO area 中的 routing DRC。
最大误区指定 -nets 不代表修 DRC 时绝对只动这些 net。

核心语法

route_eco
  [-max_detail_route_iterations count]
  [-nets nets]
  [-cells cells]
  [-shapes shapes]
  [-open_net_driven true|false]
  [-max_reported_nets limit]
  [-reroute modified_nets_only |
            modified_nets_first_then_others |
            any_nets]
  [-reuse_existing_global_route true|false]
  [-utilize_dangling_wires true|false]

-reroute 三种模式

模式行为改动倾向
modified_nets_only只动存在 open ECO change 的 nets最小，但可能修不掉
modified_nets_first_then_others先只动 modified nets，不行再动其它 fully connected nets折中，日常 ECO 很实用
any_nets允许自由 reroute 任意 net 修 DRC最大，收敛能力强

重点展开：什么叫“只动存在 open ECO change 的 nets”？

modified net因为 ECO 操作而发生了物理连接变化、当前需要重新接通的 net。
open ECO changeECO 改完后，这条 net 在物理 routing 上留下了“未完成连接 / open”。
fully connected net当前物理上已经完整连通，没有因为这次 ECO 留下 open。
modified_nets_only只允许 router 修改前一类 net；其它已连通 net 当作冻结背景。
最简单的中文：
“只动存在 open ECO change 的 nets” ≈ 只允许重新布那些因为这次 ECO 被你改断、改开、或者拓扑发生变化而还没重新接好的 net。

先区分三个概念：Modified / Open / DRC

状态含义是不是 modified net？
Modified + Open 这次 ECO 改了连接或删了 routing，导致物理连接还没完成 是，正是 modified_nets_only 主要允许修改的对象
Fully connected + DRC net 本身是连通的，但与别的 wire 太近、short、via spacing 等有 DRC 通常不是“open ECO change net”
Fully connected + clean 已经连通，也没有相关问题 不是
关键：“open ECO change”不是“只要有 DRC 就算 open”。
Open讲的是连接没完成；DRC讲的是几何规则不合法。两件事完全不同。

例 1：插一个 Buffer，为什么会产生 open ECO change？

ECO 前

U1/Z  ==============================  U2/A
             net_A 已经连通

逻辑 ECO：中间插入 BUF1

U1/Z  --------> BUF1/A
BUF1/Z --------> U2/A

逻辑拓扑已经变成两段，但原来的物理 routing geometry 还是旧拓扑，所以工具需要重新把新连接接起来。

ECO 前
U1/Z ━━━━━━━━━━━━━━━━━ U2/A
插 Buffer 后
U1/Z ── X ── BUF1/A     BUF1/Z ── X ── U2/A
Router 看到
存在因为 ECO 新拓扑造成的 open，需要 reconnect

这类 net 就是 man page 里说的 nets with open ECO changes 的典型例子。

例 2：你手工 remove 一段 shape，也会形成 open

# 原本 net_A 已经完整连通
set ss [get_shapes ...]

# 删除中间一段
remove_shapes $ss
删除前
Driver ━━━━━━━━━━━━━━━━━━━━━ Load
remove_shapes 后
Driver ━━━━━━━ X     X ━━━━━━━ Load
结果
逻辑 net 还存在，但 physical route 被切开 → open

如果这条 net 正是本次 ECO 要修的对象，那么 route_eco 会把它视作需要重新连接的 modified/open net。

例 3：另一条 Net B 没被 ECO 改过，但它挡路

Net A：ECO 后 open，需要从这里重新接
Net B：本来就是完整连通的，但正好占着 A 想走的位置
Net A
────── X         X ────── ← open ECO net
Net B
━━━━━━━━━━━━━━━━━━━━━━ ← fully connected
冲突
A 如果绕回来，可能和 B spacing 不够；移动 B 才更容易修掉

如果用 modified_nets_only

route_eco \
    -nets $eco_nets \
    -reroute modified_nets_only

Router 的思路近似于：

Net A：可以动 ✅
Net B：已经 fully connected，不许动 ❌

我要在不碰 B 的情况下把 A 接起来并满足 DRC。
如果周围空间太挤，A 根本没有合法路径，而 B 又不允许挪， 那么 modified_nets_only 就可能失败或留下 violation。

这就是三种 -reroute 的本质差别

模式 第一步 如果 modified net 自己修不掉 对已有 routing 的保护程度
modified_nets_only 只动 open ECO modified nets 不允许借助其它 fully connected nets 重绕 ★★★★★ 最强
modified_nets_first_then_others 先只动 modified nets 若还有 violation，再允许动其它 fully connected nets ★★★★☆
any_nets 不强调先保护谁 可以自由修改其它 nets 来修 DRC ★★☆☆☆
所以你可以把它们背成：
only：“只修我这次改坏的。”
first_then_others：“先只修我改坏的，实在不行再挪邻居。”
any：“谁挡路就可能重绕谁，优先把 routing 修合法。”

为什么 Synopsys 说 modified_nets_only 只适合 very minor ECO？

因为它把周围已经完整连接的 routing 都当成几乎不能动的背景。

小 ECO
只插 1 个 buffer / 只删一小段 wire
→
附近还有空 track
modified net 自己就能绕回来
→
modified_nets_only 可行
变化最小

较大 ECO
多个 cell / nets 被改
→
局部拥塞
旧 routing 把路占满
→
只动 modified nets 不够
需要挪其它 net 才能解 DRC

跟你前面“remove 一段 shape”的问题串起来

# 1) 先保存 net
set ss [get_shapes ...]
set n  [get_nets -of_objects $ss]

# 2) 删除其中一小段 route
remove_shapes $ss

# 此时：
#   逻辑 net 仍存在
#   物理连接被切开
#   n 变成需要 ECO reconnect 的对象

# 3) 如果需要，先给整条 net 新 routing rule
set_routing_rule \
    -min_routing_layer D6 \
    -min_layer_mode hard \
    $n

# 4) ECO route
route_eco \
    -nets $n \
    -reroute modified_nets_only

这时 modified_nets_only 的含义就是：

“只允许 router 改我刚刚因为 ECO 切开的这条 net；周围那些原本完整连接的 nets 都尽量保持原样。”
但 set_routing_rule 是作用于整条 net的，不是只作用于你删掉的那一小段 shape。 已经存在且未被删除的旧 shapes 通常不会因为你刚 set rule 就自动重走；真正重新生成的部分才会在 routing 时受当前 rule 约束。

一个最容易混淆的问题：open net ≠ modified net ≠ DRC net

对象连接状态是不是这次 ECO 改出来的modified_nets_only 会不会主动允许重绕
Net AOpen是会
Net BFully connected，但 spacing DRC否不会
Net CFully connected否不会

所以 man page 里说：

“freezes all the fully connected nets” 就是：先把那些已经完整接好的 net 当作不可动背景，只尝试靠 modified/open ECO nets 自己完成修复。

其它关键参数

-reuse_existing_global_route true

尽量复用已有 global route，更符合增量 ECO 思路。

-utilize_dangling_wires true

尽量复用 ECO 后留下的 dangling wires，默认 true。

-max_reported_nets

只控制最后报告多少 changed nets，不限制实际修改多少。

-open_net_driven true

不带 -nets 时，可让 DRC 修复聚焦 open net 邻域；带 -nets 时该选项被忽略。

推荐小 ECO 模板

check_routes

route_eco \
    -nets $eco_nets \
    -utilize_dangling_wires true \
    -reuse_existing_global_route true \
    -reroute modified_nets_first_then_others

完整 ECO 流程：大多数情况用 remove_routes，局部修补可用 remove_shapes

① 选择删除方式
整条 net：remove_routes
局部 geometry：remove_shapes
→
② set_routing_rule
定义 NDR、min/max layer、mode
→
③ check_routes
更新 routing violation 信息
→
④ route_eco

为什么顺序是这个？

阶段工具目的数据库变化
Remove去掉旧 routing 几何net 还在，但 wire/via 被删，可能形成 open
Set规定新 route 应遵循什么约束更新 net-based routing constraints
ECO Route按照新约束真正重布生成新的 route shapes，并修 DRC

一套完整 Tcl 示例

# ------------------------------------------------------------
# Step 0 : ECO nets
# ------------------------------------------------------------
set eco_nets [get_nets {n1 n2}]

# ------------------------------------------------------------
# Step 1 : Remove old route
# 只删 detail route，不删逻辑连接
# ------------------------------------------------------------
remove_routes \
    -nets $eco_nets \
    -detail_route \
    -keep_frozen_nets

# ------------------------------------------------------------
# Step 2 : Set routing constraints
# 主体希望走 M4~M8，但 pin connection 可以特殊越界
# ------------------------------------------------------------
set_routing_rule \
    -min_routing_layer M4 \
    -max_routing_layer M8 \
    -min_layer_mode allow_pin_connection \
    -max_layer_mode soft \
    -max_layer_mode_soft_cost high \
    $eco_nets

# ------------------------------------------------------------
# Step 3 : Update routing checks
# ------------------------------------------------------------
check_routes

# ------------------------------------------------------------
# Step 4 : ECO reroute
# 先只动 modified nets；修不掉再允许动邻近其它 net
# ------------------------------------------------------------
route_eco \
    -nets $eco_nets \
    -reroute modified_nets_first_then_others \
    -reuse_existing_global_route true \
    -utilize_dangling_wires true

这三个命令之间最核心的关系

remove_routes决定“旧线删什么”。
set_routing_rule决定“新线应该怎么走”。
route_eco决定“现在真正把它重新走出来”。
check_routes负责把当前 routing violation 信息更新到最新。

局部 shape ECO 示例

# 1) 精确拿到目标 shape
set target_shapes [get_shapes -filter "name =~ PATH_18_*"]

# 2) 删除前先保存其所属 net
set target_net [get_nets -of_objects $target_shapes]

# 3) 建议先确认 collection
sizeof_collection $target_shapes
get_object_name $target_shapes
get_object_name $target_net

# 4) 删除指定 shape
remove_shapes -verbose $target_shapes

# 5) 如果该 net 需要新的 routing 约束
set_routing_rule \
    -min_routing_layer M4 \
    -max_routing_layer M8 \
    -min_layer_mode allow_pin_connection \
    -max_layer_mode soft \
    $target_net

# 6) 重新 ECO route
check_routes
route_eco \
    -nets $target_net \
    -reroute modified_nets_first_then_others
注意：实际脚本里更稳妥的做法是，在删除 shape 前先把对应 net collection 保存到变量中，避免 shape 删除后再依赖已删除对象反查 net。

你实际做 ECO 时的检查思路

动作建议检查
remove 前确认 net 名、net type、准备删除的 shape use，避免范围过大
set rule 后确认 NDR / min-max layer / mode 是否真设到了目标 net
route_eco 后看 open、short、spacing、changed nets，以及 timing 是否受影响
尤其别直接用：remove_routes -detail_route，除非你明确就是想大范围清整个设计的 detail route。

补充：为什么小 ECO 常用 modified_nets_first_then_others？

因为它先按照 modified_nets_only 的方式保护已有 routing；只有 modified/open ECO net 自己修不掉时，才逐步允许其它 fully connected nets 参与重绕。

它本质上是：“优先最小改动，但不为了最小改动把自己卡死。”
