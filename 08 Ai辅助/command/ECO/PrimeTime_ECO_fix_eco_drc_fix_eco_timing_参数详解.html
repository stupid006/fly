01 · Big Picture

先建立 ECO 的总脑图

PrimeTime Signoff │ ├────────────── DRC / Noise ──────────────┐ │ max_transition / max_capacitance │ │ max_fanout / noise / delta_delay │ │ ▼ │ fix_eco_drc │ │ │ ▼ │ update_timing │ │ └────────────── Timing ───────────────────┤ ▼ Setup ECO │ ▼ Hold ECO │ ▼ write_changes / implement │ ▼ FC/ICC2 + route + StarRC │ ▼ 回 PrimeTime
DRC
“电气负担不合法”：slew、cap、fanout 等超限。
Noise / SI
“旁边的 net 干扰我”：noise bump 或 delta delay。
Timing
Setup 数据太晚；Hold 数据太早。
Guide 推荐的核心顺序：
DRC/Noise → Setup → Hold。原因是 DRC fixing 优先级高，可能改变 setup/hold； Setup fixing 可以引入一些 hold；Hold fixing则要尽量保护 setup 与 DRC。
02 · Iteration Strategy

DRC 修完，要不要立刻回 FC/ICC2？

修改量小：可以先留在 PT 继续

fix_eco_drc ↓ update_timing ↓ fix_eco_timing -type setup ↓ fix_eco_timing -type hold ↓ write_changes

适合：少量 resize、少量 buffer，不会明显扰动物理 placement / routing。

修改量大：建议先物理实现再回来

PT: fix_eco_drc ↓ write_changes ↓ FC/ICC2: implement / legalize / route_eco ↓ StarRC: re-extract ↓ PT: re-signoff ↓ Setup / Hold ECO

适合：大量 buffer、大量 net 拆分、明显影响 legalization / routing 的情况。

为什么不能机械地“一次全修完”？
DRC 修复本身可能改变 cell delay、slew、load 与 net topology，所以原来的 setup/hold 数值可能已经不再代表修后真实状态。 如果物理扰动明显，重新 route + parasitic extraction 后再判断 timing 更可信。
03 · fix_eco_drc

fix_eco_drc：先解决电气规则 / Noise / SI 问题

这个命令的角色： 通过 cell sizing、buffer insertion、inverter pair 等 ECO 手段，处理 max_transition、max_capacitance、max_fanout、noise、crosstalk delta delay， Guide 还包括 cell EM。默认思路是先把 DRC/Noise 处理，再进入 timing fixing。

你给的例子里最重要的用法

# 只用 sizing 修 max transition
fix_eco_drc -type max_transition -verbose \
    -methods size_cell

# 用 buffer 修 max transition
fix_eco_drc -type max_transition -verbose \
    -methods insert_buffer \
    -buffer_list {BUFX1 BUFX2 BUFX3}

# Physically aware
fix_eco_drc -type max_transition -verbose \
    -methods insert_buffer \
    -buffer_list {BUFX1 BUFX2 BUFX3} \
    -physical_mode open_site

# Noise
fix_eco_drc -type noise -verbose \
    -methods {size_cell insert_buffer} \
    -buffer_list {BUFX1 BUFX2 BUFX3} \
    -physical_mode open_site

# Delta delay
fix_eco_drc -type delta_delay -verbose \
    -delta_delay_threshold 0.05 \
    -methods {size_cell insert_buffer} \
    -buffer_list {BUFX1 BUFX2 BUFX3} \
    -physical_mode open_site

核心参数解释

-type核心
控制什么指定这次 ECO 修哪一种 violation。 常见值max_transition / max_capacitance / max_fanout / noise / delta_delay。 怎么理解不要把 DRC 看成一个模糊的大类；实际 fixing 是按具体 violation type 分开跑。 建议先 report 清楚每类数量，再按变化量最大的 DRC 类型优先处理。
-methods核心
控制什么允许工具用哪些物理/逻辑修改手段。 常见值size_cell、insert_buffer、insert_buffer_at_load_pins、insert_buffer_at_driver_pins、insert_inverter_pair。 工程含义这是在告诉工具：“你可以怎么动我的网表”。 经验先用侵入性较小的 sizing；如果 sizing 无法解决，再允许 buffer，通常比一开始就大规模插 buffer 更容易控制布局扰动。
-buffer_list核心
控制什么限定 buffer / inverter insertion 可以使用哪些 library cells。 为什么重要列表过弱会出现 unfixable reason I；列表过多、过杂又会增加搜索空间。 你的例子{BUFX1 BUFX2 BUFX3} 不够强时，命令可能修不掉 violation；文档示例建议扩大 buffer 范围。 建议给出覆盖“小/中/较强驱动”的代表性集合，不要只给一个极小 buffer。
-physical_mode open_site推荐理解
控制什么启用 physically aware fixing，并限制修改发生在已有可用空间的位置。 open_site只有存在空闲 site / 足够空间时才 resize 或插 cell；尽量不移动周围已有 cell。 典型失败unfixable reason O：没有 open free site。 意义PT 的“修得动”更接近后续 FC/ICC2 真正“放得下”。
-cell_type进阶
常见值combinational / clock_network。 默认思路先修 data path / combinational；clock network 是更敏感的后手。 clock_network可以在 clock tree 里 upsizing / 插 buffer 修 max transition/cap/fanout，但会改变 clock arrival/skew。 建议先 data path，再 clock network；clock ECO 前确认已读入 clock physical data。
-slack_lesser_than筛选范围
用途只处理 slack 比某阈值更差的对象/路径。 Noise 示例-type noise -slack_lesser_than -0.05：只修 worse than -0.05 的较大 noise violation。 Delta delay可用它限定只关注位于某 timing slack 范围内的 victim nets。 好处减少“轻微 violation”带来的大量 ECO 修改。
-delta_delay_thresholdSI
只用于-type delta_delay。 作用指定值得处理的 crosstalk delta delay cost 下限。 为什么需要delta delay 本身不像 max_transition 那样有一个“required limit → slack”，所以需要显式 threshold。 示例-delta_delay_threshold 0.05：只处理 cost 大于 0.05 time units 的 victim nets。
-verbose强烈建议
作用显示更多 fixing 信息，尤其是 remaining / unfixable violation reasons。 为什么重要你不是只想知道“修不掉”，而是要知道为什么修不掉，从而决定下一轮换方法、换 buffer、放宽 area、检查 dont_touch 或 physical site。
重要：V-2023.12 Guide 明确说 fix_eco_drc 默认并不以 timing 为主要保护目标， 所以 DRC fixing 后必须重新看 setup/hold；不要假设 DRC 修完 timing 一定不会变。
04 · fix_eco_timing

fix_eco_timing：控制“修谁、怎么修、修到什么程度、在哪里修”

fix_eco_timing
    -type setup | hold
    [-methods ...]
    [-slack_lesser_than ...]
    [-slack_greater_than ...]
    [-group ...]
    [-pba_mode none | path | exhaustive | ml_exhaustive]
    [-from ...]
    [-to ...]
    [-setup_margin ...]
    [-hold_margin ...]
    [-buffer_list ...]
    [-verbose]
    [-ignore_drc]
    [-cell_type combinational | sequential | clock_network]
    [-physical_mode none | open_site | occupied_site | freeze_silicon]
    [-path_selection_options ...]
    [-timeout ...]
    [-estimate_unfixable_reasons]
    ...
-type setup | hold必选
Setup最大延迟问题：数据太晚，目标是降低 data path delay。 Hold最小延迟问题：数据太早，目标是增加 data path delay。 注意setup 与 hold 必须分开调用；推荐先 setup，再 hold。
-methods核心
size_cell换成逻辑等价但驱动强度不同的 cell。 size_cell_side_loadSetup 专用：除了 critical path sizing，还会调整 side-load cells，降低关键 driver 的寄生负载。 insert_buffer在 driver pin、load pin 或 route 上寻找合适 buffer 位置。 insert_buffer_at_load_pins只允许 load pin 侧 buffering。 insert_buffer_at_driver_pins只允许 driver pin 侧 buffering。 insert_inverter_pair插一对 inverter；不能与普通 insert_buffer 同时作为同一种方法组合使用。 remove_bufferSetup fixing 可用，用于去掉拖慢 setup 的 buffer；不能用于 hold。
-slack_lesser_than选择谁修
含义只修 slack 比该值更差的路径。 默认0，等价于默认针对负 slack violation。 例子-slack_lesser_than -0.1：只处理 worse than -0.1 的路径。 注意它决定“选哪些 path”，不是“最终修到多少 slack”。最终目标由 margin 控制。
-slack_greater_than选择谁修
含义只考虑 slack 比该值更好的路径。 典型用途忽略极端糟糕、可能由约束错误或结构性问题导致的 violation。 组合可与 -slack_lesser_than 一起定义一个 slack 区间。 例子-slack_greater_than -2.0：不碰 worse than -2.0 的超大 violation。
-group范围
作用只修指定 path group。 例子-group {SYSCLK* IOCLK} 什么时候用某些 clock group 特别差，想分批 ECO，或避免工具把修改预算花在优先级低的 group。
-from / -to范围
作用限制 startpoint / endpoint。 与 report_timing 类似但该命令里对象限定为 pins / ports，不是 nets / cells。 什么时候用只想 ECO 某个 block interface、某一批 endpoints、某个 SRAM interface。
-setup_margin目标 slack
Setup fixing 时正值 = overfix 到正 slack；负值 = underfix，只改善到允许的负 slack。 Hold fixing 时它变成“必须保护的 setup margin”。 例子-type setup -setup_margin 0.1：目标是让被选中的 setup path 尽量达到 +0.1。 关键margin 不决定选哪些 path；路径选择由 slack_lesser/greater 等控制。
-hold_margin目标 slack
Hold fixing 时正值 = overfix 到正 hold slack；负值 = underfix。 Setup fixing 时它变成“必须保护的 hold margin”。 例子-type setup -setup_margin 0.2 -hold_margin 0.1：修 setup 的同时保护至少 0.1 hold margin。
-buffer_list核心
作用指定插 buffer / inverter pair 时允许使用的 library cell base names。 无默认 list要用 insertion 方法，必须给可用 cell list。 Hold 建议覆盖所需 delay 范围，不要塞一堆极其相似的 buffer，避免 runtime 增加却没收益。 Setup 建议优先选择 drive 好、delay 短的 buffer。
-pba_mode分析精度
none默认，GBA；最快。 path对 GBA 已抓到的路径做 PBA recalculation。 exhaustive完整 exhaustive PBA 搜真正 worst path；更准、更慢。 ml_exhaustive机器学习加速 exhaustive，前期大 TNS/大量 violation 更适合；接近 signoff 时结果/开销趋向 exhaustive。
-ignore_drc慎用
默认行为存在 max_transition / max_capacitance / max_fanout 的 timing path，timing fixing 默认不会直接硬修。 加上后允许 timing 优先，即使可能恶化 DRC。 建议只放到 ECO 后期：已经尽量把 DRC 修完，但 DRC 保护成为剩余 timing 的阻碍时再考虑。
-cell_type修改对象
combinational默认；修改 data path combinational cells。 sequential通过 sizing sequential cell 修输入/输出相关 timing；只支持 size_cell。 clock_network改 clock path 来改变 clock arrival；可能影响 skew，属于更敏感的后手。 建议先 combinational；不够再考虑 sequential / clock_network。
-physical_mode物理可实现性
none默认，不使用 physical data。 open_site只有现成空位才插/放大，保留已有 placement；后期 ECO 更稳。 occupied_site允许暂时与邻近 cell overlap，只要密度允许后续 implementation tool 挪出空间；fix rate 更高但扰动更大。 freeze_silicon只利用预定义 spare cells，不新插普通 cell、不任意 size。
-path_selection_options高级范围控制
作用把一组 get_timing_paths 风格的选路参数交给 ECO，用更复杂条件定义 fixing scope。 互斥不能同时与 -from/-to/-group/-pba_mode/-slack_lesser_than/-slack_greater_than 使用。 注意因为只修被选中的 paths，修后 QoR 检查也要使用相同 path selection 条件。
-timeoutRuntime
作用限制命令总 wall-clock runtime。 不设置工具不直接按总时间停，而会根据 QoR、fix rate、继续迭代的预期收益决定是否继续。
-verbose推荐
作用输出更详细 fixing 信息；DMSA 下可看到各 scenario violation 信息。 配合变量设置 eco_report_unfixed_reason_max_endpoints 为正数后，可生成 Unfixable Violations 报告。
-estimate_unfixable_reasons预检查神器
作用只分析“为什么可能修不掉”，不真正修改设计。 什么时候用正式 ECO 前先检查 buffer list、physical site、dont_touch、margin 是否会成为瓶颈。 建议对于大规模 hold ECO，先跑一次能减少盲目尝试。
-load_cell_listHold 微调
用途Hold fixing 使用 load capacitance cell / dummy load，适合几 ps 量级的小 hold violation。 与 buffer_list 共用工具可以小 violation 用 load cell，大 violation 用 buffer。 优点比插完整 buffer 更细粒度、面积通常也更小。
-clock_fixes_per_changeClock ECO
仅作用于-cell_type clock_network 默认1。 含义一次 clock tree 修改至少要能修多少 violating endpoints 才值得做。 值变大修改数更少，倾向在更高层、更靠近 clock source 的位置做 ECO。
-clock_max_level_from_regClock ECO
仅作用于-cell_type clock_network 默认0，表示不限制。 例子1 = 只允许在 register clock pin 的 immediate driver 层附近修改；2 = 再允许往上一层。 意义限制 clock ECO 的影响范围，值越小越局部。
-target_violation_type endpoint | tnsClock ECO
endpoint默认；不允许为了改善整体而进一步恶化已有 violating endpoint。 tns允许个别 endpoint 变差，只要整体 TNS 改善；受 WNS 下限保护。 限制用于 clock network fixing。
-wns_limitClock ECO
配合-target_violation_type tns 作用规定允许牺牲 endpoint slack 时，WNS 最差不能低于多少。 默认当前已有 WNS。
-current_library搜索空间
作用sizing 时只从原 cell 所在 library 选替代 cell。 优点候选更少，runtime 可能更好。 代价可用替代 cell 变少，QoR/fix rate 可能下降。
-power_attribute / -power_mode功耗
作用Timing fixing 时不只考虑 area，也把 leakage / dynamic / total power 纳入选择。 默认不指定时主要倾向最小化 area 影响。 注意属于进阶 power-aware ECO，需要相应 power data / attribute。
05 · Fixing Methods

Methods 不是“参数名字”，而是工具真正会做的动作

Method主要用途适合风险 / 注意
size_cell换 drive strength / 等价 cellSetup、Hold、DRCUpsize 可能增加 load/power/area；downsize 可能恶化 setup。
size_cell_side_load调整 critical path + side loadsSetup仅 setup；通过减 side-load cap 帮关键 driver。
insert_buffer拆负载、改善 slew、增加/减少局部 delaySetup、Hold、DRC、Noise会改变 net topology，可能显著增加 physical disturbance。
insert_buffer_at_load_pins只在 load 侧插精细控制比通用 insert_buffer 搜索范围窄。
insert_buffer_at_driver_pins只在 driver 侧插精细控制同上。
insert_inverter_pair用两级 inverter 保持逻辑极性DRC / Timing 特殊场景要给 inverter list；与普通 buffer insertion 有组合限制。
remove_buffer删除拖慢 setup 的 bufferSetup不能造成新 DRC / worsening hold。
一个很好用的思路：Setup ECO 如果要用 buffer，先尝试 sizing，再尝试 buffer insertion； 文档明确说明这样通常能减少 buffer 数量和 layout disturbance。
06 · Physical Awareness

open_site / occupied_site 到底差在哪

open_site
只有已经存在足够空间时才做修改。
优点：预测性好、扰动小。
缺点：高利用率区域容易 reason O —— “No open free site”。
occupied_site
允许先产生 overlap，只要局部 density 允许后续 implementation tool 挪 cell 腾空间。
优点：fix rate 更高。
缺点：legalization / routing 扰动更大。
ECO 早期 / violation 很多 ↓ occupied_site（更 aggressive） ↓ 收敛 ↓ ECO 后期 / 想少扰动 ↓ open_site（更 conservative）
不要混用逻辑 ECO 与 physical ECO： 一旦同一个 PT session 已经加载 physical data 并用 open_site/occupied_site 做 fixing， man page 建议后续继续保持 physically aware fixing，不要又切回 -physical_mode none 做 what-if 修改， 否则 physical database 与逻辑修改可能失去一致性。
07 · PBA

none / path / exhaustive / ml_exhaustive

模式怎么做Runtime建议场景
none普通 GBA最快大量 violation、早期快速 ECO
path对已收集路径进行 PBA recalculation中快速看 PBA 能释放多少 pessimism
ml_exhaustive机器学习加速 exhaustive 搜索中~高大量 violation / 高 TNS，想比 exhaustive 更省 runtime
exhaustive exhaustive PBA 搜 truly worst paths最高剩余少量难修路径、接近 signoff
你之前问的重点：ml_exhaustive 不是“AI 直接决定插哪个 buffer”， 而是用机器学习加速 PBA path search / violation identification，让 ECO 的 timing 判断更高效。
08 · Unfixable Reasons

看到修不掉，不要立刻换更大 buffer——先看 reason code

Code含义你下一步应该想到什么
A可用 lib cell 超出 area limit检查 eco_alternative_area_ratio_threshold / 是否允许更大 cell。
B单级 delay 改善不足以修掉 timing可考虑 underfix、分阶段修、换 fixing point。
Cviolation 在 clock network默认 data path ECO 不动 clock；必要时显式 clock_network。
D高密度区域物理空间不足；检查局部 utilization。
Ephysical 信息缺失/不可用查 LEF/DEF/physical DB 一致性。
H逻辑与物理 hierarchy 不一致先修数据库一致性，不是换 buffer 能解决。
I给定 buffer_list 修不掉扩大/调整 buffer delay/drive 范围。
L可用物理面积限制候选 lib cell空间问题，不只是 library 问题。
ONo open free siteopen_site 没位置；看 filler / spacing / 周边布局。
PDRC driver 是 portport 不能像 cell 一样 resize；考虑 buffering。
Q可能是 sequential driver（DRC 示例）或 clock fixing 下 launch/capture conflict结合具体命令类型判断；clock ECO 要特别小心。
Rparasitics 没 location 或 location transform 失败检查 parasitic location / mapping。
Ssizing 找遍替代 cell 也修不掉换 buffer insertion 等方法。
Ttiming margin 太紧目标 constraint/保护 margin 限制了 fixing。
UUPF 限制isolation/retention/level shifter/always-on 等特殊 cell 限制。
Vdont_touch / invalid检查 dont_touch 是否合理。
WTiming fixing 会恶化 DRC说明 DRC protection 卡住了 timing；后期才考虑 -ignore_drc。
推荐用法：
正式大修前先设置： 
set_app_var eco_report_unfixed_reason_max_endpoints 50

fix_eco_timing -type hold \
    -buffer_list $HOLD_BUF_LIST \
    -estimate_unfixable_reasons
先判断“为什么修不掉”，再决定是不是值得真正跑 ECO。
09 · Practical Recipes

我建议你实际按这几层跑

Recipe A：常规 Physically Aware ECO 
# ---------- 0. 基线 ----------
set_app_var timing_save_pin_arrival_and_slack true
update_timing

# report DRC / timing first
report_constraint -max_transition -all_violators
report_constraint -max_capacitance -all_violators
report_constraint -max_fanout -all_violators
report_timing -delay_type max
report_timing -delay_type min

# ---------- 1. DRC ----------
fix_eco_drc -type max_transition \
    -methods {size_cell insert_buffer} \
    -buffer_list $DRV_BUF_LIST \
    -physical_mode open_site \
    -verbose

# 按需要继续 cap / fanout / noise
# fix_eco_drc -type max_capacitance ...
# fix_eco_drc -type max_fanout ...
# fix_eco_drc -type noise ...

update_timing

# ---------- 2. Setup ----------
fix_eco_timing -type setup \
    -physical_mode open_site \
    -verbose

update_timing

# ---------- 3. Hold ----------
fix_eco_timing -type hold \
    -methods {size_cell insert_buffer} \
    -buffer_list $HOLD_BUF_LIST \
    -physical_mode open_site \
    -pba_mode exhaustive \
    -verbose

# ---------- 4. 导出 ----------
write_changes -format icctcl -output pt_eco.tcl
Recipe B：Setup violation 很多，先快后准 
# 前期大量 violation
fix_eco_timing -type setup \
    -pba_mode none \
    -physical_mode open_site \
    -verbose

# 收敛后重新评估
update_timing

# 剩余关键 path 用更高精度
fix_eco_timing -type setup \
    -pba_mode ml_exhaustive \
    -physical_mode open_site \
    -verbose

# 最后少量 hard path 再 exhaustive
fix_eco_timing -type setup \
    -pba_mode exhaustive \
    -physical_mode open_site \
    -verbose
Recipe C：Hold 先估计，再真修 
set_app_var eco_report_unfixed_reason_max_endpoints 50

# 先不改设计
fix_eco_timing -type hold \
    -buffer_list $HOLD_BUF_LIST \
    -physical_mode open_site \
    -estimate_unfixable_reasons

# 看 reason I/O/T/V/W 等，再决定参数

# 真正 fixing

最后只记 8 句话也够用

1. DRC/Noise 用 fix_eco_drc，Timing 用 fix_eco_timing。
2. 顺序优先记：DRC/Noise → Setup → Hold。
3. -methods 决定“工具允许怎么改网表”。
4. -buffer_list 决定“插什么 cell”。
5. -physical_mode 决定“是否考虑真实能不能放得下”。
6. -pba_mode 决定“timing 判断的精度/runtime”。
7. -margin 决定“修到什么 slack”，不是决定“选谁修”。
8. 修不掉先看 unfixable reason，不要盲目重复跑。
