冯诺依曼瓶颈：
经典架构中，**指令和数据共用存储器及传输资源**，取指令和读写数据可能争用通路。同时，CPU 的计算速度与主存提供数据的能力存在差距，导致 CPU 等待
                       (CPU计算速度 >>内存提供数据的速度)
即使计算单元能做得更快，也可能受限于内存带宽
![[附件/09-lecture/计算机与智能处理器体系结构/02-存储层次与访问路径.png]]

dark silicon
**Dark Silicon（暗硅）指的是：芯片上虽然集成了大量晶体管，但由于**功耗和散热限制，不能让所有晶体管同时全速工作**。必须关闭或降低其中一部分电路的运行频率
产生暗硅的核心原因是：**晶体管数量增长得比供电和散热能力更快。**

过去晶体管缩小时，电压也能相应降低，更多晶体管可以在相近功耗下工作，这称为 **Dennard Scaling（登纳德缩放）**。后来电压难以继续大幅下降，而动态功耗近似为：

$$
P_{\text{dynamic}} \approx \alpha C V^2 f
$$

其中：

- $\alpha$：电路活动率
- $C$：等效电容
- $V$：电压
- $f$：时钟频率

晶体管越来越多，如果全部同时翻转，功耗和温度就会超过芯片能够承受的范围。

常见应对方法包括：

- **时钟门控**：暂时不工作的电路停止时钟，降低动态功耗。
- **电源门控**：切断某个模块的供电，使其真正关闭。
- **动态调压调频**：降低电压和频率。
- **异构计算**：用专用加速器完成特定任务，以更少功耗完成相同工作。
- **任务迁移**：根据温度和功耗，在不同核心或模块之间移动任务。

“暗硅”并不意味着坏掉或永久不能用，而是**某一时刻不能使用的芯片面积**。与它相近的说法还有 **Dim Silicon（灰硅或弱亮硅）**，指电路仍在运行，但只能以较低电压或频率运行。


## 2026-09-13：从 MAC 一路串到 Pipeline 和 STA

今天最大的收获不是又记住了几个名词，而是第一次把以前零散看到的寄存器、Memory、MAC、流水线和 timing path 连成了一条线。

以前做数字后端时，看到的往往是：

```text
FF → combinational logic → FF
```

或 timing report 里的 startpoint、cell/net 和 endpoint。今天开始意识到，这些路径并不是一串没有含义的门；它们上面正跑着某条指令所需要的数据。

### 极简 RISC：先把访存和计算拆开

课程用的是教学用的极简 RISC，不是说所有真实 RISC 都只有这四条指令。它用 `Load / Store / MOV / MAC`，把 ISA、数据通路和一个神经元计算先讲明白。

![[附件/09-lecture/计算机与智能处理器体系结构/03-极简RISC指令集.png]]

我现在对四条指令的理解是：

- `MOV`：把立即数（这里也可看作地址常量）送进寄存器。
- `Load`：按“基址寄存器 + offset”读 Memory，再写进 `rd`。
- `Store`：把寄存器里的数据写回 Memory。
- `MAC`：只负责寄存器数据之间的计算/累加，不直接到 Memory 中找操作数。

所以数据路径可以先粗略记成：

```text
Memory ──Load──> Register ──MAC──> Register ──Store──> Memory
```

这里最关键的是 **Load/Store Architecture**：访存与计算分开。不是“RISC 不访问内存”，而是只有明确的 Load/Store 指令去访问内存，计算指令主要在寄存器之间工作。

### MAC 的 funct=0/1：先初始化，再滚动累加

一开始只看指令表时，我不确定 `funct` 是什么。结合二输入神经元的完整程序后，语义就清楚了：

```text
funct = 1：rd = rs1
           用 rs1 初始化/重置累加结果

funct = 0：rd = rd + rs1 × rs2
           做 Multiply-Accumulate
```

因此这里的 MAC 很像一个“滚雪球”的累加过程，而不只是普通乘法。

![[附件/09-lecture/计算机与智能处理器体系结构/04-二输入神经元MAC汇编.png]]

二输入神经元：

$$
y=b+x_1w_1+x_2w_2
$$

可以拆成：

```asm
MOV   R1, [ADB]
Load  R2, R1, $0        // R2 = b
MAC   R5, R2, /,  $1    // R5 = b，初始化累加值

MOV   R1, [ADX]
MOV   R2, [ADW]
Load  R3, R1, $0        // R3 = x1
Load  R4, R2, $0        // R4 = w1
MAC   R5, R3, R4, $0    // R5 = b + x1*w1

Load  R3, R1, $1        // R3 = x2
Load  R4, R2, $1        // R4 = w2
MAC   R5, R3, R4, $0    // R5 = b + x1*w1 + x2*w2

MOV   R1, [ADY]
Store /,  R1, R5        // Memory[ADY] = y
```

这里顺便发现 PPT 最后一条 MAC 右侧的注释写成了 `R5=b+x2w2`，少写了已经累加进去的 `x1w1`；按前面的 MAC 语义，实际结果应当是：

$$
R5=b+x_1w_1+x_2w_2
$$

到这里，算法到硬件的第一段链路已经出现了：

```text
神经元公式 → Load/MAC/Store → Register File/MAC/Memory
```

### RISC vs CISC：今天纠正了两个太绝对的说法

我最开始的理解是：RISC 把访存设计成单独的 Load/Store，其他指令只做 compute，所以更容易使用简洁、定长的指令和分段流水线；CISC 把访存和计算放在一条指令里，所以不能定长、不能流水线。

这个理解的主线有价值，但后半句说得太绝对。

更准确的说法应该是：

> RISC **倾向于**采用 Load/Store 架构，让指令格式、数据通路和执行阶段更规则，因此更容易做简单译码、流水线和高频实现。CISC 允许一条指令完成更复杂的工作，可能同时包含访存和计算，操作数形式、指令长度和执行延迟通常更复杂，因此前端译码和流水线控制更难，但绝不是不能流水线。

今天纠正的两个点：

1. **RISC 不等于永远定长。**例如 RISC-V 的基础指令常见为 32 bit，但也有 16 bit 压缩指令。
2. **CISC 不等于不能流水线。**现代 x86 一样有很深的流水线，常把复杂指令译成较规则的 micro-ops 后再执行。

所以现在不再用“简单 vs 复杂”四个字死记，而是抓住：

```text
RISC：访存显式、寄存器运算为主、格式和执行流程更规则
CISC：单条指令表达的工作更多、寻址和译码更复杂
```

### Load/Store 会不会让冯诺依曼瓶颈更严重？

看到 `Load → Load → MAC → Store` 后，我一度把“RISC 指令可能更多”直接等同成“Memory 访问一定更多”。这也是今天一个重要纠偏。

Load/Store 架构只要求算术指令不直接访问内存，并不要求每次计算都重新 Load。例如数据 Load 一次后，可以一直留在寄存器里供多个 `ADD/MUL/MAC` 重用。因此：

> **指令条数增加，不等于数据内存流量一定增加。**

即使 CISC 把 `Memory Read + MAC + Write Back` 包装进一条指令，硬件底层仍然要把 `x`、`w` 搬到计算单元。指令写得短，并没有消灭数据搬运。

冯诺依曼瓶颈真正关心的是 CPU 与存储系统之间的 **latency 和 bandwidth 差距**。RISC 和 CISC 都躲不开，只能通过寄存器复用、多级 Cache、prefetch、乱序执行等办法尽量减少或隐藏等待。

不过原来的直觉也不是完全没有意义：若同一个任务需要更多、更宽的指令，确实可能增加 I-Cache 和取指带宽压力；这属于代码密度/取指问题，不能和数据访存流量混为一谈。

### Single-cycle：CPI=1 只是 Iron Law 的一项

![[附件/09-lecture/计算机与智能处理器体系结构/05-Single-Cycle与Iron-Law.png]]

Single-cycle 看起来很漂亮，因为每条指令一个周期：

$$
CPI=1
$$

但按照 Iron Law：

$$
T_{program}=IC\times CPI\times T_{clk}
$$

只把 CPI 做到 1，并不代表程序一定快。单周期设计要求最慢的那条指令也必须在一个周期内走完，因此时钟周期要覆盖最慢路径。

例如 Load 可能需要依次经过：

```text
PC/Instruction Memory
        ↓
Decode / Register File Read
        ↓
Address Calculation
        ↓
Data Memory Read
        ↓
MUX / Register File Write
```

如果这条路径需要 4 ns，那么：

$$
T_{clk}\ge 4ns,\qquad f_{max}\le 250MHz
$$

哪怕 MOV 只需要 0.5 ns，也必须等满这个 4 ns 周期。

这和数字后端的经验其实是同一件事：架构课说“clock period 由最慢 datapath 决定”，STA 说“frequency 被 critical path 限制”。以前看到的 setup violation、WNS 和 frequency closure，不是后端凭空制造出来的；架构先决定要经过哪些逻辑，后端再在这个前提下尽量把物理路径收敛到目标周期。

### Pipeline：切短 critical path，主要换来 throughput

Pipeline 在较长的组合逻辑之间插入寄存器：

```text
Single-cycle：IF + ID + EX + MEM + WB

Pipeline：    IF | ID | EX | MEM | WB
                 ↑    ↑    ↑     ↑
              pipeline registers
```

这样一条很长的 reg-to-reg path 被切成多条短路径，更容易提高频率。对 STA 来说，每一级重新变成较短的 `FF → combinational logic → FF`。

但流水线主要提高的是 **throughput**，不一定降低单条指令的 **latency**：

- 一条指令可能仍要走 4～5 个 cycle 才完成，加入流水寄存器后还有 clock-to-Q、setup 和时钟偏差等开销。
- 流水线填满后，多条指令可以重叠，理想状态下几乎每个 cycle 都完成一条。

因此不能只说“流水线让一条指令变快”，更准确的是：它把长路径切短、提高工作频率，并让多条指令重叠执行，从而提高单位时间完成的指令数。

### Data Hazard：并行以后，RAW 依赖暴露出来了

![[附件/09-lecture/计算机与智能处理器体系结构/06-RAW数据冒险.png]]

图里的核心序列是：

```asm
LOAD R3, R1
LOAD R4, R2
MAC  R5, R3, R4
```

`MAC` 要读 `R3/R4`，但前面的 Load 还没有完成写回，后面的读就可能拿到旧值。这是 **RAW（Read After Write）**：后面的 Read 依赖前面的 Write。

```text
LOAD R4：产生并写入 R4
                    ↓
MAC：               读取 R4
```

它不是程序语义有错，而是指令重叠以后，“需要数据的时刻”早于“数据可用的时刻”。

### NOP、Stall、Bubble：有关联，但不是同一个东西

最直接的办法是让 MAC 晚一点：

```asm
LOAD R3, R1
LOAD R4, R2
NOP
MAC  R5, R3, R4
```

现在对三个词的区分是：

- **NOP**：ISA 中一条真正“什么也不做”的指令，可以由程序员/编译器显式放进去。
- **Stall**：硬件暂时冻结某些流水级，让有关指令先别往前走。
- **Bubble**：stall 后注入流水线的空操作/无效槽，它沿流水线继续移动。

可以用这条因果链记忆：

```text
检测到 hazard → stall 某些流水级 → 向后级注入 bubble
```

课件把 `NOOP (Bubble/Stall)` 写在一起，是为了先表达“空等一个周期”；严格说三者并不完全等价。课件只需要一个 bubble，还隐含了寄存器堆能在同一周期先 write、后 read（或等效时序安排）的假设。

Bubble 没有完成有用工作，所以会令实际 CPI 上升、IPC 下降。流水线虽然把频率推高了，hazard 又会把一部分吞吐吃掉，这正好回到 Iron Law：性能不能只看 frequency。

### Forwarding / Bypassing：数据已经产生，就别绕寄存器堆一圈

如果前一条指令的结果已经在某个流水级末端产生，只是还没正式写回 Register File，那么可以直接把这个结果送到后续运算单元输入：

```text
正常路径：结果 → RF-WRITE → RF-READ → MAC input

Forwarding：结果 ─────────────────→ MAC input
```

Forwarding 和 Bypassing 基本是在说同一种思想：绕过尚未完成的寄存器写回/重读路径，把最新值直接送给依赖指令。代价是增加旁路网络、MUX、比较与 hazard control；这些电路本身也会进入 timing、面积和功耗权衡。

同时要记住：**forwarding 只能转发已经产生的数据，不能让数据提前出现。**普通 ALU-to-ALU 依赖常能靠 forwarding 消掉停顿；而经典五级流水线里紧邻的 load-use 依赖，Load 的数据通常到 MEM 末端才得到，下一条指令在 EX 开头就要使用，因此常常仍需一个 bubble。具体需要停几拍，要看实际流水级划分和旁路路径。

### 今天形成的理解链路

今天真正想留下的是这条链，而不是一组孤立定义：

```text
算法：y = b + x1*w1 + x2*w2
  ↓
汇编：Load / MAC / Store
  ↓
ISA：rd / rs / imm / funct
  ↓
Datapath：Register File / MAC / MUX / Memory
  ↓
Single-cycle：CPI=1，但 critical path 很长
  ↓
Pipeline：切短 timing path，提高 frequency 和 throughput
  ↓
指令重叠：出现 RAW data hazard
  ↓
处理：stall / bubble / NOP / forwarding
  ↓
物理实现：FF → combinational logic → FF
  ↓
STA：setup / critical path / WNS / frequency closure
```

以前我是从最下面的 cell、net、buffer、setup/hold 往上看；今天开始能反过来问：为什么会有这条 timing path？因为 RTL 在实现 datapath；为什么需要这条 datapath？因为 ISA 要执行指令；为什么需要这些指令？因为最上面的算法要真正算出结果。

这应该就是继续学体系结构对数字后端最有价值的地方。
