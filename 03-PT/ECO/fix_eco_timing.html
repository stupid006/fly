面向 PrimeTime ECO timing fixing 的中文速查资料。本文依据用户提供的 Synopsys fix_eco_timing man page（文档标注版本：U-2022.12-SP5）重新组织撰写，保留命令、参数、取值、关键约束和实用示例，但不是原手册的逐句翻译。不同工具版本的行为可能有差异，执行前请以当前安装版本的 man fix_eco_timing 为准。

1. 命令用途

fix_eco_timing 通过工程变更（ECO）修复或改善 setup（最大延迟）与 hold（最小延迟）违例。常见动作包括：

  • 将实例替换为逻辑等价、驱动能力不同的 library cell；
  • 在数据路径或时钟网络中插入 buffer / inverter pair；
  • 在特定条件下绕过或删除已有 buffer；
  • 利用 placement、空闲 site、spare cell 等物理信息生成更容易落地的 ECO；
  • 在多场景、PBA、功耗约束下选择修改方案；
  • 分析未能修复的违例及其原因。

命令返回 status。实际 ECO 修改保存在当前 PrimeTime session 中，可再用 write_changes 导出。

2. 语法

TCL / PRIMETIME
fix_eco_timing \
    -type setup|hold \
    [-methods method_list] \
    [-slack_lesser_than slack_limit] \
    [-slack_greater_than slack_limit] \
    [-group group_name] \
    [-pba_mode none|path|exhaustive|ml_exhaustive] \
    [-from from_list] \
    [-to to_list] \
    [-setup_margin margin] \
    [-hold_margin margin] \
    [-buffer_list list] \
    [-verbose] \
    [-current_library] \
    [-ignore_drc] \
    [-cell_type combinational|sequential|clock_network] \
    [-physical_mode none|open_site|occupied_site|freeze_silicon] \
    [-path_selection_options option_string] \
    [-timeout seconds] \
    [-power_attribute power_attribute_name] \
    [-clock_fixes_per_change violation_limit] \
    [-clock_max_level_from_reg level_limit] \
    [-estimate_unfixable_reasons] \
    [-power_mode total|dynamic|leakage] \
    [-leakage_scenario scenario_name] \
    [-dynamic_scenario scenario_name] \
    [-load_cell_list list] \
    [-target_violation_type endpoint|tns] \
    [-wns_limit wns_value] \
    [-unfixable_reasons_format text|csv] \
    [-unfixable_reasons_prefix string]

时间值使用当前 library time unit。例如，当时间单位为 ns 时，0.05 表示 50 ps。

4. 参数详解

4.1 -type setup | hold

必选参数。

  • setup：处理 maximum-delay / setup timing violation。
  • hold：处理 minimum-delay / hold timing violation。

当设计同时存在 setup 与 hold 违例时，常见顺序是先 setup、后 hold。原因是 setup fixing 可能引入新的 hold 风险，而 hold fixing 会尝试避免造成新的 setup 或 DRC 问题。最终仍应按项目 flow 和 signoff 策略复核。

4.2 -methods method_list

指定允许使用的 ECO 方法。

method 作用 主要限制/适用范围
size_cell 用逻辑等价但 drive strength 不同的 cell 替换路径上的 cell setup/hold 均可用
size_cell_side_load 除路径 cell 外，也考虑 driver fanout 上的 side-load cell，以降低关键路径寄生负载 仅 -type setup；setup 默认 method
insert_buffer 在 driver pin、load pin 或 route 上插 buffer 需要 -buffer_list；setup 插 buffer 需要 physical mode
insert_buffer_at_load_pins 仅在 load pin 附近插 buffer hold fixing 可用；不要同时指定普通 insert_buffer 来表达“仅 load”
insert_buffer_at_driver_pins 仅在 driver pin 附近插 buffer setup fixing 可用；不要同时指定普通 insert_buffer 来表达“仅 driver”
insert_inverter_pair 插入两级 inverter，保持逻辑极性不变 需要 inverter -buffer_list；不能与 insert_buffer 同用
bypass_buffer 绕过 clock network 中的 buffer 或 inverter pair 仅配合 -cell_type clock_network
remove_buffer 删除 buffer，以改善 setup，并尽量不恶化 hold/DRC 仅 setup；必须单独使用；另有多项互斥参数

setup fixing 的要点：

  • sizing 可选 size_cell 或 size_cell_side_load，默认是 {size_cell_side_load}；
  • insert_buffer 可单独使用，也可与 sizing 组合，但 -physical_mode 必须为 open_site 或 occupied_site；
  • freeze_silicon 模式只允许 insert_buffer；
  • insert_buffer_at_driver_pins 用于把位置限定在 driver pin。

hold fixing 的要点：

  • 可使用 size_cell、insert_buffer、insert_buffer_at_load_pins、insert_inverter_pair；
  • 默认是 {size_cell insert_buffer}；组合使用时，工具会先尝试 sizing，再考虑插 buffer，以减少新增 cell 和版图扰动；
  • insert_buffer_at_load_pins 用于把插入位置限定在 load pin。

remove_buffer 的特殊限制：

  • 不能用于 hold fixing；
  • setup fixing 中不能与其他 method 组合；
  • 不能与 -cell_type、-power_attribute、-current_library、-load_cell_list、-timeout、-unfixable_reasons_format、-unfixable_reasons_prefix、-power_mode 同用。

4.3 -slack_lesser_than slack_limit

只处理 slack 比给定值更差的路径，即：

REFERENCE
slack < slack_limit

默认值为 0，因此默认目标是 negative-slack violation。

TCL / PRIMETIME
-slack_lesser_than -0.1

表示只处理比 -0.1 更差的路径；-0.05 不在本轮范围内。

如果要把正 slack 路径也纳入 overfix，需要把上限设为正值，并配合正 margin。例如：

TCL / PRIMETIME
fix_eco_timing -type setup \
    -slack_lesser_than 0.2 \
    -setup_margin 0.2

4.4 -slack_greater_than slack_limit

只处理 slack 比给定值更好的路径，即：

REFERENCE
slack > slack_limit

这个参数常用于跳过极严重、可能来自 design/constraint 问题的违例。例如：

TCL / PRIMETIME
-slack_greater_than -2.0

可把修复范围限制在 -2.0 以上。两个 slack 参数可组合：

TCL / PRIMETIME
-slack_greater_than -0.5 \
-slack_lesser_than 0

大致表示只处理：

REFERENCE
-0.5 < slack < 0

4.5 -group group_name

只修指定 path group 中的路径。支持：

  • 单个 group 名称；
  • 多个 group 的 Tcl list；
  • wildcard；
  • get_path_groups 返回的 collection。
TCL / PRIMETIME
fix_eco_timing -type setup -group {SYSCLK* IOCLK}

4.6 -from from_list / -to to_list

分别限定 timing path 的 startpoint 和 endpoint：

TCL / PRIMETIME
fix_eco_timing -type setup \
    -from [get_pins REG_A/Q] \
    -to   [get_pins REG_B/D]

与 report_timing / get_timing_paths 的同名参数不同，这里只能指定 pin 或 port，不能直接传 cell 或 net。

4.7 -pba_mode none | path | exhaustive | ml_exhaustive

值 含义 特点
none 普通 GBA，不启用 PBA 默认；最快
path 先由 GBA 收集路径，再对路径做 PBA 精度高于纯 GBA
exhaustive exhaustive PBA，寻找真正的 worst-case path 最精确、计算量最大
ml_exhaustive 机器学习辅助的 exhaustive PBA 在 flow 中权衡 runtime 与精度，接近 signoff 时趋近 exhaustive 的结果与开销

所选模式既影响违例识别，也影响修复过程使用的 timing 结果。

4.8 -setup_margin margin

单位为 library time unit，默认 0。

  • setup fixing 中：指定目标 setup slack；正值表示 overfix，负值表示 underfix。
  • hold fixing 中：指定修 hold 时希望保护的最小 setup margin。

注意：margin 不会自动扩大路径选择范围。默认没有被选中的正 slack 路径，不会仅因为设置了正 margin 就被修改。若要处理正 slack 路径，需要同时调整 -slack_lesser_than。

4.9 -hold_margin margin

单位为 library time unit，默认 0。

  • hold fixing 中：指定目标 hold slack；正值 overfix，负值 underfix。
  • setup fixing 中：指定修 setup 时希望保护的最小 hold margin。

未显式设置 margin 时，工具也会尝试保护 DRC 和另一类 timing，但其行为不一定完全等同于显式指定 -setup_margin 0.0 -hold_margin 0.0。

4.10 -buffer_list list

指定 buffer insertion 可使用的 buffer，或 insert_inverter_pair 可使用的 inverter。

TCL / PRIMETIME
-buffer_list {BUFX1 BUFX2 DLYX1 DLYX2}

关键规则：

  • 使用 insert_buffer 或 insert_inverter_pair 时必须提供；没有默认 list；
  • 使用 library cell 的 base name，例如 BUFX2，通常不写成 mylib/BUFX2；
  • 工具按 link_path 中的 library 顺序搜索，遇到第一个同名 cell 即使用；
  • list 中的 cell 即使 dont_use=true，仍可用于 buffer insertion；dont_use 只限制 cell sizing；
  • hold 下组合 {size_cell insert_buffer} 时，工具可能先插 list 中的 buffer，再把它 size 成未显式列入 list 的其他 buffer。

4.11 -load_cell_list list

指定可沿 data path 使用的 load-capacitance cell、buffer 或 inverter，主要配合 hold 的 insert_buffer 方法处理几 ps 量级的小违例。

TCL / PRIMETIME
-load_cell_list {CLOAD1 CLOAD2}

它可以单独使用，也可以与 -buffer_list 同时使用。

4.12 -verbose

打印更多修复过程信息。在 DMSA 中会显示各 scenario 的违例信息。

若以下变量被设为正整数，-verbose 还会在真正执行 fixing 后生成 Unfixable Violations 报告：

TCL / PRIMETIME
set_app_var eco_report_unfixed_reason_max_endpoints 50

DMSA flow 中，该变量需要在 manager 上设置。

4.13 -estimate_unfixable_reasons

只做 fixing analysis，不真正修改当前 design；用于估算哪些违例难以修复以及原因。使用前同样必须把 eco_report_unfixed_reason_max_endpoints 设为正整数。

TCL / PRIMETIME
set_app_var eco_report_unfixed_reason_max_endpoints 50

fix_eco_timing -type hold \
    -buffer_list {BUFX1 BUFX2} \
    -estimate_unfixable_reasons

重要：运行日志里即使出现类似“多少 cell 被 resized”的过程性统计，也只是分析中的模拟 change，不会保留为实际设计修改，因此没有可供 write_changes 导出的真实 ECO。

4.14 -unfixable_reasons_format text | csv

设置 unfixable reasons 报告格式：

  • text：文本格式；
  • csv：可供 PrimeTime GUI 或电子表格使用；
  • 未指定该参数时，若启用了文件输出，则默认同时生成 text 与 csv。

4.15 -unfixable_reasons_prefix string

设置报告文件名前缀。只有提供该参数才会实际生成独立报告文件。

TCL / PRIMETIME
-unfixable_reasons_prefix abc \
-unfixable_reasons_format csv

会生成类似：

REFERENCE
abc_eco_tim.csv

4.16 -current_library

cell sizing 时只允许从原 cell 所属 library 中选择 replacement。候选更少，通常可改善 runtime，但也可能降低 QoR。

4.17 -ignore_drc

默认情况下，路径上已有 max_transition、max_capacitance 或 max_fanout 违例时，工具不会继续做 timing fixing。使用 -ignore_drc 后可忽略这些限制继续尝试，但可能新增或恶化 DRC，适合作为明确接受风险后的手段，而非默认选项。

4.18 -cell_type combinational | sequential | clock_network

值 修改对象 说明
combinational data path 上的组合逻辑 cell 默认
sequential sequential cell 只支持 -methods size_cell
clock_network 时钟网络中的组合 cell 可 sizing、插入或 bypass，以改变 clock arrival time

可以只指定一种，也可以用 {combinational sequential} 同时处理组合与时序 cell。sequential 与 clock_network 修改可能影响较大，通常先尝试 combinational，不足时再考虑其他类型。

4.19 -physical_mode none | open_site | occupied_site | freeze_silicon

值 物理行为 适用提示
none 不使用 physical data 默认；setup buffer insertion 不允许使用此模式
open_site 只有周围空间足够才 size；只有空 site 足够才插 buffer；不移动邻近 cell 保守，适合 late/post-route ECO
occupied_site density 允许时，可让新/变大 cell 暂时与邻近 cell overlap 后续必须由 ICC2 等 implementation 工具移动邻近 cell 并合法化
freeze_silicon 只利用已定义的 programmable spare cell；不新增 cell、不 resize 现有 cell 只允许 insert_buffer，配合 ICC2 freeze-silicon flow

physical-aware session 的一致性很重要：一旦在当前 PrimeTime session 中用 open_site 或 occupied_site 做过 fixing，建议后续继续使用 physical-aware fixing，不要再切回 none，也尽量避免直接运行 what-if size_cell / insert_buffer。混用可能使逻辑 ECO 与物理数据库状态不一致，给实现阶段带来明显版图扰动。

freeze_silicon 使用前需要通过 set_eco_options -programmable_spare_cell_names 标识 spare cell；可以用 report_eco_options 检查当前配置。

4.20 -path_selection_options option_string

把与 ECO timing fixing 相关的 get_timing_paths 选择条件交给命令，用于精确限定路径。

TCL / PRIMETIME
fix_eco_timing -type setup \
    -path_selection_options {
        -through u01/A
        -to ff0/D
        -max_paths 10
        -nworst 5
    }

限制：

  • 不能与 -from、-to、-group、-pba_mode、-slack_lesser_than、-slack_greater_than 同用；
  • 只支持 get_timing_paths 中与 ECO fixing 相关的选项；
  • 内含 collection 时，整个参数字符串必须放在 {} 中；
  • 除非使用 -start_end_pair 或 -cover_design，否则应显式给出适合 ECO 的 -max_paths 与 -nworst；
  • 修复后应使用同一组 path selection options 运行 get_timing_paths 或 report_timing，以正确评估 QoR。

4.21 -timeout seconds

设置整个命令的最大 wall-clock runtime。工具在每轮 fixing iteration 结束时检查，因此不是严格到秒的硬中断。未设置时，工具会按 QoR、fix rate 及继续迭代的预期收益决定何时结束。

4.22 -power_attribute power_attribute_name

指定一个用户定义的 lib-cell attribute，代表 worst leakage corner 下的 leakage 值。工具会优先选择 leakage 较低的替代 cell；未指定时默认优先考虑 area。

4.23 -power_mode total | dynamic | leakage

使用 PrimePower 数据在 timing fixing 中考虑功耗：

  • dynamic：只考虑动态功耗；
  • leakage：只考虑漏电功耗；
  • total：同时考虑 dynamic 与 leakage。

使用前必须已有 update_power 或 report_power 产生的 power analysis data。

互斥限制：

  • 不能与 -power_attribute 同用；
  • 不能与 -cell_type clock_network 同用。

setup 下也会影响 size_cell_side_load 的候选选择；hold 下会影响 sizing 与 buffer insertion 的选择。未指定时默认优化倾向仍是 area，而不是 power。

4.24 -leakage_scenario scenario_name

DMSA 中使用 -power_mode 时，指定提供 leakage 数据的 scenario，通常应选择 worst-leakage scenario。

4.25 -dynamic_scenario scenario_name

DMSA 中使用 -power_mode 时，指定提供 dynamic power 数据的 scenario，通常应选择 worst-dynamic scenario。它可以与 leakage scenario 相同，也可以不同。

4.26 -clock_fixes_per_change violation_limit

仅在 -cell_type clock_network 时生效。规定每一次 clock sizing、buffer insertion 或 inverter-pair insertion 至少要改善多少个 leaf sequential endpoint violation。默认值为 1。

值调大可减少 clock network ECO 数量，并倾向于只做影响范围更大的修改，但也可能降低 fix rate。

4.27 -clock_max_level_from_reg level_limit

仅在 -cell_type clock_network 时有意义，用于限制从 leaf sequential clock pin 向上游允许修改的 clock-tree 层数。例如 1 只允许修改紧邻寄存器 clock pin 的 leaf-level driver。设置更高可扩大范围；关闭限制则允许更上游的 clock ECO。

4.28 -target_violation_type endpoint | tns

仅可用于 -cell_type clock_network。

值 目标
endpoint 默认；逐 endpoint 改善 slack，不恶化已有 endpoint violation
tns 以整体 TNS 改善为目标；只要 TNS 变好，允许部分 endpoint 进一步恶化到当前 WNS 或指定的 -wns_limit

tns 需要 PrimeTime-ADV license。

4.29 -wns_limit wns_value

只配合 -target_violation_type tns 使用，指定允许的 WNS 下限。默认是运行命令前的现有 WNS。

例如当前 WNS 为 -0.100，某 endpoint 为 -0.060。在 TNS 模式下，该 endpoint 可能被恶化到 -0.100，只要整体 TNS 变好；若设置 -wns_limit -0.080，则最多只允许恶化到 -0.080。

5. Unfixable Violation Report

5.1 如何生成

真正执行 ECO 并在结尾报告：

TCL / PRIMETIME
set_app_var eco_report_unfixed_reason_max_endpoints 50

fix_eco_timing -type hold \
    -buffer_list {BUFX1 BUFX2 BUFX3} \
    -physical_mode open_site \
    -verbose

只分析、不修改 design：

TCL / PRIMETIME
set_app_var eco_report_unfixed_reason_max_endpoints 50

fix_eco_timing -type hold \
    -buffer_list {BUFX1 BUFX2 BUFX3} \
    -physical_mode open_site \
    -estimate_unfixable_reasons

输出独立 CSV 文件：

TCL / PRIMETIME
fix_eco_timing -type hold \
    -buffer_list {BUFX1 BUFX2 BUFX3} \
    -verbose \
    -unfixable_reasons_prefix hold_try1 \
    -unfixable_reasons_format csv

5.2 表格标记和优先级

  • S：一段 violating path 的起点；
  • E：path endpoint，该行的 Prio/slk 显示整条路径 slack；
  • C：与之前路径共享的片段之后，从最后一个共享点继续；
  • P0 到 P9：候选 pin 的 fixing priority / bottleneck 排名，P9 最高、P0 最低。高优先级位置通常更值得优先人工排查或放宽限制。

报告按 worst slack path 优先排列；一条路径内部按 startpoint 到 endpoint 的顺序显示。

5.3 完整 reason code

Code 中文含义 常见检查或处理方向
A 有可能有效的 library cell，但其面积超过候选面积上限 检查 eco_alternative_area_ratio_threshold；评估放宽面积上限
B 当前 stage 能获得的 delay 改善太小，无法完全修掉违例 检查违例是否过大；可用负的 -setup_margin / -hold_margin 做 underfix，先取得部分改善
C 违例位于 clock network 默认不碰 clock network；先尝试 combinational / sequential，必要时评估 -cell_type clock_network
D cell 或 net 位于高 density 区域，附近空间不足 在 implementation 工具检查局部 utilization、placement 与 filler；必要时腾挪空间
E physical information 不完整或不可用，或相关 net 在 DEF 中被标记为 +USE CLOCK 检查 DEF/LEF 与当前 netlist 是否一致，确认 physical data 配置
H logical hierarchy 与 physical hierarchy 不一致，无法插 buffer 在 implementation 工具中解决 netlist/layout 层级不一致
I 给定 -buffer_list 中的 cell 无法通过插 buffer 修复 扩大 buffer 类型、drive strength 或 delay-cell 范围后重新估算
L 可用物理面积限制了一个或多个本可使用的 library cell 在 implementation 工具中增加附近可用面积或换更小候选
M clock ECO 可修复的 leaf-cell violation 数低于阈值 仅 clock fixing；调低 -clock_fixes_per_change
N clock-tree 位置的层级高于允许阈值 仅 clock fixing；调高或关闭 -clock_max_level_from_reg 限制
O route 上或附近没有可用 open free site 检查 LEF/DEF、filler 识别和 spacing rule；在 implementation 工具中创建空 site
Q 同一 FF 的 capture 与 launch 侧违例冲突，改变 clock arrival 会顾此失彼 仅 clock fixing；分别检查 D/Q 两侧 setup/hold，优先考虑 data-path 方案或修改约束/结构
R parasitics 中没有 buffer insertion 所需的坐标，或 location transformation 失败 检查寄生文件是否含 location，以及层级/坐标映射
S 所有 alternative library cell 都尝试过，cell sizing 仍无法修复 考虑 buffer insertion、结构性 ECO 或放宽其他限制
T timing margin 太紧，目标违例与 opposite constraint 之间没有足够余量 复核 setup/hold margin；明确接受风险时可用负 margin 放宽目标
U UPF 限制该位置的 sizing 或 buffering 检查 always-on、isolation、retention、level-shifter 等 UPF cell 限制
V cell/net 无效，或相关对象带 dont_touch 检查 dont_touch 是否必要、对象是否有效，以及层级对象解析
W 修 timing 可能产生或恶化 DRC 检查 transition/capacitance/fanout；明确接受 DRC 风险时才考虑 -ignore_drc

补充说明：

  • 当 eco_allow_filler_cells_as_open_sites=true（手册所述默认值）时，physical-aware ECO 会把 filler cell 当作 open site；
  • advanced-node spacing rule 可能使看似空闲的 site 实际宽度不足，因此 O 不一定只是“没有空白格”；
  • M、N、Q 专用于 clock-network fixing 的诊断。

6. 典型用法

6.1 Setup：默认 sizing

TCL / PRIMETIME
fix_eco_timing -type setup

setup 默认 method 是 {size_cell_side_load}。

6.2 Setup：只修指定 slack 区间

TCL / PRIMETIME
fix_eco_timing -type setup \
    -slack_greater_than -0.3 \
    -slack_lesser_than 0

表示只处理约 -0.3 < slack < 0 的路径。

6.3 Setup：overfix，同时保护 hold

TCL / PRIMETIME
fix_eco_timing -type setup \
    -setup_margin 0.05 \
    -hold_margin 0.02

目标是把已选中的 setup violation 尽量修到 +0.05，同时尽量保留至少 +0.02 的 hold margin。

6.4 Hold：只用 sizing

TCL / PRIMETIME
fix_eco_timing -type hold \
    -methods size_cell

6.5 Hold：physically-aware sizing + buffer insertion

TCL / PRIMETIME
fix_eco_timing -type hold \
    -methods {size_cell insert_buffer} \
    -buffer_list {BUFX1 BUFX2 DLYX1 DLYX2} \
    -hold_margin 0.02 \
    -setup_margin 0.05 \
    -physical_mode open_site \
    -verbose

6.6 Hold：仅在 pin 附近插 buffer

TCL / PRIMETIME
fix_eco_timing -type hold \
    -methods {
        insert_buffer_at_load_pins
        insert_buffer_at_driver_pins
    } \
    -buffer_list {BUFX1 BUFX2 BUFX3}

6.7 Hold：用 inverter pair

TCL / PRIMETIME
fix_eco_timing -type hold \
    -methods insert_inverter_pair \
    -buffer_list {INVX1 INVX2 INVX4}

6.8 Hold：几 ps 小违例使用 load cell

TCL / PRIMETIME
fix_eco_timing -type hold \
    -methods insert_buffer \
    -load_cell_list {CLOAD1 CLOAD2} \
    -slack_greater_than -0.005

也可同时给普通 buffer：

TCL / PRIMETIME
fix_eco_timing -type hold \
    -methods insert_buffer \
    -load_cell_list {CLOAD1 CLOAD2} \
    -buffer_list {BUFX1 BUFX2}

6.9 用 PBA 选择 hold 路径

TCL / PRIMETIME
fix_eco_timing -type hold \
    -pba_mode exhaustive \
    -buffer_list {BUFX2 DLY1X2 DLY2X2}

6.10 精确指定 timing paths

TCL / PRIMETIME
fix_eco_timing -type setup \
    -path_selection_options {
        -through u01/A
        -to ff0/D
        -max_paths 10
        -nworst 5
    }

6.11 同时 size sequential 与 combinational cell

TCL / PRIMETIME
fix_eco_timing -type setup \
    -cell_type {sequential combinational} \
    -methods size_cell

6.12 Clock network fixing

TCL / PRIMETIME
fix_eco_timing -type setup \
    -cell_type clock_network \
    -clock_fixes_per_change 4 \
    -clock_max_level_from_reg 2

用 inverter pair 修改 clock network：

TCL / PRIMETIME
fix_eco_timing -type setup \
    -methods insert_inverter_pair \
    -cell_type clock_network \
    -buffer_list {INVX1 INVX2 INVX4}

6.13 TNS-driven clock ECO

TCL / PRIMETIME
fix_eco_timing -type setup \
    -cell_type clock_network \
    -target_violation_type tns \
    -wns_limit -0.10

该模式以 TNS 改善为目标，允许个别 endpoint 在不越过 -0.10 的前提下变差。执行前确认 PrimeTime-ADV license 和项目对 WNS degradation 的接受标准。

6.14 Setup：删除已有 buffer

TCL / PRIMETIME
fix_eco_timing -type setup \
    -methods remove_buffer

remove_buffer 必须单独使用，并遵守前文列出的互斥限制。

6.15 不改设计，先诊断

TCL / PRIMETIME
set_app_var eco_report_unfixed_reason_max_endpoints 50

fix_eco_timing -type setup \
    -methods size_cell \
    -group reg2reg \
    -estimate_unfixable_reasons \
    -unfixable_reasons_prefix setup_dryrun \
    -unfixable_reasons_format csv

7. 导出实际 ECO 修改

真正运行 fix_eco_timing 后，用 write_changes 把当前 session 中的修改写成可供其他 PrimeTime session 或 implementation tool 使用的 Tcl：

TCL / PRIMETIME
fix_eco_timing -type setup \
    -methods size_cell \
    -group reg2reg

write_changes -format icctcl eco_setup.tcl

导出的脚本可能包含：

TCL / PRIMETIME
size_cell U123 BUF_X4

physical-aware buffer insertion 还可能带 location 信息，例如：

TCL / PRIMETIME
insert_buffer U2/Z BUF2X -location {200.0 300.0 0}

注意：

  • -estimate_unfixable_reasons 不会真实修改 design，因此不会产生可导出的实际 change；
  • 日志中的 change 次数不一定等于最终脚本命令数。例如一个新插入的 buffer 后续又被 resize，日志可能计作两次 change，而 write_changes 会合并成插入最终尺寸 buffer 的一个最终动作；
  • 判断“最终到底改了什么”时，应以 write_changes 导出的脚本和 implementation 后的验证结果为准。

8. 推荐工作流程

REFERENCE
1. 检查约束、异常大违例、DRC、dont_touch、UPF 与 physical data
2. 先用 combinational setup fixing
3. 导出并在 implementation 环境实现、合法化、重新抽取寄生
4. 重新分析 setup/hold/DRC/power
5. 再做 hold fixing，并保护 setup margin
6. 数据路径仍不足时，谨慎评估 sequential 或 clock-network ECO
7. 用 unfixable report 定位物理空间、候选 cell、margin 或约束瓶颈
8. 最终以实现后重新提取的 signoff timing 为准

尤其是 clock-network bypass、插入或其他会改变 net topology 的 ECO，PrimeTime 中的估算不能替代 implementation、合法化、重新抽取寄生后的 signoff 验证。

9. 常见误区

  1. 把 -setup_margin 当成路径筛选条件。 margin 是修复目标；选择哪些路径主要由 -slack_lesser_than 等参数决定。
  2. 以为设置正 margin 会自动 overfix 所有正 slack 路径。 默认只修改已被选择的目标路径；要包含正 slack 路径，需调整 -slack_lesser_than。
  3. 使用 insert_buffer 却不提供 -buffer_list。 该方法没有默认 buffer list。
  4. 把 library/cell 写进 -buffer_list。 通常应给 base name，并注意同名 cell 按 link_path 顺序匹配。
  5. 把 cell/net 直接传给 -from 或 -to。 这里仅接受 pin/port。
  6. 把 -estimate_unfixable_reasons 当作真实 ECO。 它是 dry-run 风格的分析，不保留修改。
  7. 在同一 session 先做 physical-aware ECO，后切回 -physical_mode none。 这可能破坏逻辑和物理数据库的一致性。
  8. 看到 W 就无条件加 -ignore_drc。 这只是把风险转移到 DRC，必须由后续实现和 signoff 验证承担。
  9. 认为 open site 一定能放 cell。 advanced-node spacing、blockage、cell 宽度和 filler 识别都可能让“看起来空闲”的位置不可用。
  10. 把 PrimeTime 中的估算结果当作最终 signoff。 ECO 落地后应重新 placement/legalization、route、extract，并复查所有 scenario。

10. 相关命令和设置

常见关联项：

  • write_changes：导出最终 ECO changelist；
  • set_eco_options / report_eco_options：配置和检查 physical/freeze-silicon/多场景 ECO 选项；
  • get_timing_paths / report_timing：按相同筛选条件验证 fixing 前后路径；
  • group_path / get_path_groups：建立和选择 path group；
  • implement_eco：在支持的 implementation flow 中实现 ECO；
  • eco_report_unfixed_reason_max_endpoints：控制 unfixable report 的 endpoint 数；
  • eco_alternative_area_ratio_threshold：限制 alternative cell 的面积比；
  • eco_allow_filler_cells_as_open_sites：控制 physical-aware ECO 是否把 filler 视为 open site；
  • eco_enable_mim：控制 Multiply Instantiated Module 的一致性 ECO。

本文是工程速查版，不代替当前 Synopsys 版本的正式命令手册、许可说明和项目 signoff 规范。
