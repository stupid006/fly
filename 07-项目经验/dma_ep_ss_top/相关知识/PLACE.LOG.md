## 2. 优化成本表与 R2R-COST

![[Pasted image 20260916141342.png]]

![[Pasted image 20260916141321.png]]

**补充复习：**

| 关注项 | 读法 |
| --- | --- |
| `SETUP-COST` | 看 setup 优化趋势；不要直接等同于报告中的带符号 TNS |
| `R2R-COST` | 看寄存器到寄存器路径的优化趋势，同时检查时钟和时序约束 |
| `HOLD-COST = 0` | 不能据此证明所有路径都没有 hold 违例 |
| `LDRC-COST` | 结合 transition / capacitance 的具体违例数量与最差值阅读 |

**R2R 更能反映实现质量的前提是约束正确。** 它仍受时钟周期、uncertainty、时序例外、derate 和 scenario 等影响，因此截图中的“违例一定是实现问题”“IO 违例可以带账”不能直接作为判断标准。

HTML 纠错版记录：最终全设计 `R2RTNS = 491.1`；FuncTT 的 `reg2reg` 仍有 **8,446** 条违例、TNS **−495.8 ns**。这说明已明显改善，但尚未 clean；两组数字属于不同统计口径。

## 8. 为什么 final_place 后指标反而变差

![[final_place指标反弹_原讨论_db3c78ad.png]]

**原问题：为什么 final_place 相比 initial_opto 会恶化，不应该越来越好吗？**

### 本次数据：反弹后修复，但未完全恢复

下表沿用已有 HTML 解析中的检查点。NSV、MaxTrnV、MaxCapV 为原解析记录的违例数量，R2RTNS 为日志的非负成本 / 幅值口径；不是带符号的路径 slack。

| 指标 | initial_opto 出口 | final_place 出口 | final_opto 后最终检查点 |
| --- | ---: | ---: | ---: |
| NSV | 29,125 | 60,108 | 30,821 |
| MaxTrnV | 850 | 8,351 | 978 |
| MaxCapV | 1,614 | 4,317 | 2,020 |
| R2RTNS | 260.3 | 2,659.9 | 491.1 |

能直接读出的结论是：**final_place 检查点的这些指标恶化，后续优化又明显改善，但最终仍高于 initial_opto 出口。** 这描述了本次趋势，尚不能证明反弹的唯一原因或结果是否可接受。

### 为什么不保证每一步都更好

放置和优化需要同时考虑时序、拥塞、面积与合法位置等因素。Synopsys 的产品资料也将放置、合法化、拥塞估算与物理优化列为相互配合的能力，但没有据此承诺每个阶段的每项指标都单调改善。[参考：Fusion Compiler 官方资料](https://www.synopsys.com/content/dam/synopsys/implementation%26signoff/datasheets/fusion-compiler-ds.pdf)

结合本次记录，可以作如下理解：

1. **位置变化可能改变原有时序条件。** 单元移动后，相关网络的线长、寄生 RC 与负载可能变化；此前的尺寸选择和 buffer 位置未必仍合适。因此 setup、transition 或 capacitance 违例可能增加，但不是所有网络都会变差。
2. **本次还存在门控拓扑与约束变化。** `final_place` 中执行了 ICG 合并，且出现 `CSTR-013`。应同时检查这些变化，不能把全部反弹直接归因于移动单元。
3. **后续优化在新的设计状态上继续改善指标。** 本次 `final_opto` 后违例明显减少，符合继续修复的趋势；是否满足目标仍需看同口径报告与项目门限。

以上是结合流程记录的机制解释，具体归因仍需比较前后路径报告、寄生参数、网表变化及约束。

### 如何判断这次反弹是否可以接受

- **先确认可比性**：场景、约束、统计对象、RC 分析口径以及时序更新状态是否一致。
- **再定位变化**：抽查新增或恶化路径，对比 cell delay、net delay、slew、cap，以及 ICG 合并前后的时钟路径与约束。
- **检查获得了什么改善**：拥塞热点和合法化结果是否确有改善，不能只假设“时序牺牲换来了可布性”。
- **最后按项目门限判断**：结合最终 WNS / TNS、DRV、hold 和布线风险；“后续修回来一部分”本身不等于通过。

**记忆句：全流程追求收敛，不保证每个中间检查点都更好；反弹需要解释和验证，不能仅凭阶段名认定正常。**
